# Changelog

All notable changes to OpenPluginSDK are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are described in [docs/VERSIONING.md](docs/VERSIONING.md).

Entries describe what changes for someone writing a plugin with the SDK, and are written from the git history. Each release names its commit range. `v0.1.0-beta.1` and `v0.4.0-beta` are tagged; the releases between them are identified by the commit that bumped the version in `Cargo.toml`. Breaking changes are marked **Breaking**.

Before 1.0 the SDK does not promise compatibility between releases: any release may break. Breaking changes are listed under Changed or Removed and marked.

## [Unreleased]

### Added

- Track name in the Audio Unit and AAX. `Plugin::track_info_changed` and `Editor::track_info` now hear the track's name from an Audio Unit host (`kAudioUnitProperty_ContextName`, as Logic sets it) and from Pro Tools (`AAX_eNotificationEvent_TrackNameChanged`), through the existing `op_shell_set_track_info` and `op_editor_set_track_info`; no ABI change. `colour` is `None` and `kind` is 0 there: neither format has a call for a track's colour or kind. Both shells tell the plugin on the main thread (the AAX data model hops to the main dispatch queue when Pro Tools notifies from another thread; on Windows it calls on the notification's thread, never the audio thread), and both views tell the editor on the main thread. A name equal to the last one is not repeated, a new engine is told again, and a removed or empty name arrives as `None`. LV2 delivers nothing: no published LV2 extension carries a track's name or colour. Proofs `au_track_proof` and `aax_track_proof`, with the editor off and on ([docs/EDITOR.md](docs/EDITOR.md#the-hosts-parameter-menu-and-the-track)). The AAX view on Windows does not tell the editor yet.
- Porting guides (porting toolkit task 5, [docs/PORTING.md](docs/PORTING.md#porting-guides)): one guide each for iPlug2, DPF, nih-plug, JUCE and the raw VST3, CLAP and Audio Unit SDKs in `docs/porting/`. Each maps that SDK's processor, parameters, state, editor, buses, MIDI and threading onto this SDK's and ports a small effect in full (a gain with a meter and an editor, a low-pass with presets, a sidechain ducker, an echo that reads the old plugin's XML state, a tempo-locked tremolo, a note-opened gate, a parametric EQ band), then lists what has no counterpart yet. Every code block is a doc test of the new `examples/porting_guides` crate (`publish = false`) and each port runs the conformance kit with the allocation check, so the guides stop compiling when the API they describe changes. Docs and an example only: no SDK API changed.
- Identity pins (porting task 2, [docs/PORTING.md](docs/PORTING.md#identity-pinning)): a plugin can set every id a host stores, so a port from another SDK is the same plugin to a host, and a parameter table can be reordered or extended without breaking saved projects. New module `openplugin_core::identity`. Plugin ids: `Plugin::clap_id`, `Plugin::vst3_ids` (`Vst3Ids::from_hex` and `processor_from_hex`, the 32 hex digits a scan prints) and `Plugin::au_ids` (`AuIds`), beside the existing `aax_ids` and `lv2_uri`; all default to `None`. Parameter ids: `ParamInfo::with_host_id(n)` pins the CLAP `param_id`, the VST3 `ParamID` and the `AudioUnitParameterID`, `with_clap_id`, `with_vst3_id` and `with_au_id` pin one format, and `with_aax_id("...")` the AAX parameter id; they are kept in the new field `ParamInfo::pins` (`ParamPins`, empty by default and left out when a `ParamInfo` is serialized). `identity::check_pins(&plugin)` names every pin a format cannot carry (a repeated id, a reserved one); such a set is ignored as a whole for its format. `ParamIdMap` is the table the entries use. **A plugin without pins is unchanged**: the same ids in every format and the same state bytes, held as literals in `tests/identity.rs` of the editor, Role Tags and Expression Synth examples.
- A table with any pin saves its parameters by id: `OPST` version 2 (`SNAPSHOT_VERSION_KEYED`), each value under its `ParamInfo::id`. `decode_params` reads it into any table: a value goes to the parameter of the same id, a parameter the state does not name gets its default, a value without a parameter is dropped, and a state that names none of the table's parameters is refused. A positional (version 1) state read by a pinned table lands by old position (value `i` on the parameter whose CLAP id is `i`), so a released plugin can pin its parameters at their positions and reorder afterwards. A table without pins writes and reads version 1 exactly as before.
- `examples/pinned` (`example-pinned`, and the static libraries `example-pinned-a`, `-b`, `-plain-a`, `-plain-b` in `builds/`): the identity proof's plugin in two parameter orders, with and without pins. `tests/session.rs` is the CLAP proof; `vst3_identity_proof`, `au_identity_proof` and `aax_identity_proof` are the native ones (built when the four libraries are next to `OP_RUST_LIB`): a project saved with one build opens in the other, with the unpinned builds as the negative control.
- `scripts/build_plugin.sh --au-type auto|aufx|aumu|aumf` (`OP_AU_TYPE`), and `--au-subtype` / `--au-manufacturer` may be left out for a plugin that pins its codes with `Plugin::au_ids`.

### Changed

- Shell ABI 8 (`op_shell.h`): `op_shell_identity`, `op_shell_param_host_id`, `op_shell_param_aax_id` and `op_shell_au_code`, in one block at the end; nothing existing changed. A shell built from this header refuses a library older than ABI 8, as for every ABI version; a stand-in library written by hand needs the four calls (`native/include/stub_identity.h` answers them for a plugin without pins). The VST3, Audio Unit and AAX shells take their parameter ids from the library: for a plugin without pins those are the indices and the string ids they always were. With pinned VST3 parameter ids the component state's head is version 2 (values by `ParamID`); with pinned Audio Unit ids the unit keeps its parameters by id and lists them in table order; an AAX chunk of another parameter layout is read through the plugin blob when the plugin has pins, and refused as before when it has none.
- The CLAP entry skips a parameter event whose `param_id` the plugin does not have. For a plugin without pins that is an id past the end of the table, which had no effect before either.
- `native/CMakeLists.txt` asks the plugin for pinned Audio Unit codes at configure time (`au/kind_probe.c codes`). A plugin that pins codes gets them in its `Info.plist` when the build gives none, and a build that gives different codes stops. A plugin without pinned codes builds as before.
- `openplugin-port scan` writes the pins: `.with_clap_id(n)`, `.with_vst3_id(n)` or `.with_au_id(n)` on every parameter when the source's ids are not positions, `fn vst3_ids` with the scanned class ids, and `fn au_ids` with the scanned codes (the build line then leaves `--au-subtype` and `--au-manufacturer` out). The `TODO(porting task 2)` lines are gone; an id a format cannot carry gets a `TODO` that says why. `openplugin-port` now depends on `openplugin-core`.
- CLAP `voice-info` and `CLAP_EVENT_NOTE_END` (0.7 task 4): `VoiceInfo`, `Plugin::voice_info` and `Plugin::pull_note_end` in core (defaulted to `None`, so nothing changes for a plugin that does not opt in); `VoiceAllocator::voice_info`, `pop_ended`, `ended_len` and `ENDED_CAPACITY` in `openplugin-dsp`. The CLAP entry offers `voice-info` and sends one `NOTE_END` per ended voice after each block, without allocating. Expression Synth uses both and is now also a `cdylib`, which CI's clap-validator job checks.
- The Audio Unit shell reports `kAudioUnitProperty_SupportsMPE`, from the new `OP_NOTE_PORT_MPE` bit of `op_shell_note_ports` (set for a plugin whose `mpe_input` is `Some`; a library without it reads as no MPE). Proven by `au_mpe_proof` and `au_mpe_proof_off`.

### Fixed

- A plugin without identity pins that adds parameters at the end of its table reads the states of its earlier builds. A positional state with fewer values than the build has parameters used to be refused whole, so the first update that added a control lost every saved setting in VST3 and Pro Tools. It now loads onto the first parameters and the rest take their defaults: the OPST version 1 plane (`decode_params`, so CLAP, LV2 and the blob of `op_shell_load_state`), the version 1 head of the VST3 component state, and the AAX chunk (which also checks that its layout hash is that of the shorter table). A state with more values, or none, is still refused. **Changed behaviour:** an unpinned build that also reorders or removes parameters no longer refuses an older, shorter state in CLAP, LV2, VST3 and the Audio Unit; its values land by position. Such a table needs pins ([docs/SHELL.md](docs/SHELL.md#older-states-of-a-plugin-without-pins)).
- Audio Unit: an old preset (no `OpenPluginState` key) whose data held a value that was not finite left that value in the unit, and every render then failed with `kAudioUnitErr_InvalidParameter`: a silent track. After the base class's restore, a value that is not finite or is out of range is put back to the parameter's default, and such a value no longer fails a render.
- VST3: `setBusArrangements` on an active processor changed the channel counts under buffers sized for the old layout (stereo to 5.1 wrote past the bypass buffers on the audio thread). It is refused while the processor is active.
- VST3: parameter names and units outside ASCII were garbled ("Größe" read "GrÃ¶ÃŸe"); they are converted from UTF-8 like the value text.
- VST3, Audio Unit: a state restored before the engine exists (`setState` before `setActive`, `RestoreState` before `Initialize`, which is how hosts open a session) built a whole engine to check the blob, destroyed it, and built another on activation. The first engine is kept and adopted when the rate, block size and layout still match.
- VST3, Audio Unit, AAX: every block pushed, or asked for, every parameter across the ABI (in VST3 a taper conversion each). A block now makes a parameter call only for a value the engine may not hold; a steady block makes none.
- VST3, Audio Unit: one main-thread timer per process polls every instance for changes, in place of a timer per instance. Audio Unit: MIDI output targets replaced by a new `kAudioUnitProperty_MIDIOutputCallback` are freed, all but the last. AAX: the controls packet is filled from cached parameter objects into one reused buffer, not by a search by string id and an allocation per change.
- AAX: `GetChunk` saved the plugin's state twice (a size query, then the copy) and `CompareActiveChunk`, which Pro Tools calls often for its Compare light, did the same and wrote every parameter value into the engine on each call. Each now runs one `op_shell_save_state`, into a buffer of the size the state had last time; compare returns at the first parameter that differs, without a save, and never writes to the engine. Proven by `aax_state_blob_proof`, which counts the calls.
- Audio Unit: more than 1,024 events between two renders (a MIDI flood, or long parameter ramps beside notes) were refused one by one and nothing counted them, so note-offs were lost. A full queue now drops its oldest parameter event to make room, and with none waiting its oldest event that is not a note-off; drops are counted (private property `kOpenPluginAUProperty_EventsDropped`) and the view logs them. `au_events_proof` pushes 1,100 events between two renders and every note-off arrives.
- `openplugin-dsp` precision: `SampleVoice` keeps its playhead in `f64` (an `f32` one drifted 5 cents sharp from 5 s, played a semitone flat from 60 s and stuck on one sample past 2^24 samples); `Biquad` keeps coefficients and state in `f64` and computes `1 - cos(w0)` as `2 sin^2(w0/2)` (a 20 to 40 Hz shelf or low-pass was up to 1.2 dB off at 96 and 192 kHz); `WindowRms` sums in `f64` (it read -66.7 dBFS on silence after ten minutes of loud noise). No API changed.
- `SurroundAdapter` / `StereoOnSurround` forward `param_modulation`, `track_info_changed`, `note_on_ref`, `note_off_ref`, `note_expression` (to every engine), `note_expressions`, `mpe_input`, `voice_info` and `pull_note_end` (from the first engine); a wrapped plugin answered these with the trait defaults. With `LfeMode::Pass` the LFE is delayed by the inner plugin's latency, so it no longer comes out early against the other channels.
- `VoiceAllocator` holds `N + ENDED_CAPACITY` ended notes, so every voice can end in one block, and counts the ones it still has to drop (`ended_dropped`).
- CLAP: a block with more than 256 events dropped its late note-offs and MIDI, which could leave notes stuck. Past the schedule, a note-off or MIDI event now reaches the plugin at once (out of order), and the queued start of the same note, if no end follows it, is withdrawn so the early end cannot leave it sounding.
- CLAP: each batch of parameter events at one sample position copied and scanned every parameter. The batch's own parameters now go to the plugin directly, in the same order and with the same values as before, and the full pull at each chunk is skipped while the parameter plane's revision has not moved. New `ParamCursor::pull_index`, `pulled` and `mark_pulled`.
- `Seqlock::publish` makes the odd sequence visible before the slot write on weakly ordered CPUs (ARM): a reader could accept a torn frame.

- Editor views: a host callback made from inside an editor call can no longer re-enter the editor or free the view under it. On macOS the tick timer runs in every run-loop mode, so a host that opened a menu or dialog from `on_context_menu` or `on_edit_request` got a second tick, draw or mouse call while the first was on the stack; the Cocoa view now refuses the nested call and repaints afterwards, as the Windows view does. Closing the editor from inside such a callback (dropping the Cocoa or Win32 `EditorView`, CLAP `gui.destroy` or LV2 `cleanup` on X11) now takes effect when the call returns.
- Windows: pasted text is read only as far as its clipboard block goes (`GlobalSize`), so a block without a terminating NUL is no longer read past its end; a key the view forwards to a parent that sends it straight back is passed to the system instead of forwarded again.
- LV2 UI (`ui:CocoaUI`, `ui:X11UI`, `ui:WindowsUI`): opening the editor no longer constructs a plugin each time; the index of the first parameter port is read once per process.
- Linux: when the X connection is lost, the CLAP gui unregisters its descriptor with the host (it stays readable and the host would call `on_fd` without end), and the LV2 UI's `idle` returns non-zero so the host closes it. New `x11::EditorView::usable` and `x11::EditorView::dead`.
- macOS: the accessibility sync no longer asks the editor for its node count and every node on each tick while no assistive client has asked for the view's children.
- `SceneCanvas`: a design too large for 64 M device pixels (a 256 MB framebuffer) is drawn at a lower scale instead of allocating it; an ordinary design keeps the scale it asked for.
- CLAP: an instrument's audio output named input port 0 as its in-place pair, though it has no input port; clap-validator failed its two out-of-place processing tests on Expression Synth. The main ports are now a pair only when both exist.
- X11: a right click on the view while the type-in field was open showed the parameter menu and closed it at once, when the field had taken the focus: the focus going back to the host was taken for focus leaving the view. The X11 services tests now use the X server's own clock for event times, so they no longer pass or fail by how long the machine has been up.
- `openplugin-dsp`, bad input no longer panics or latches (DSP audit findings 1, 2, 4, 10, 11, 13 and 16):
  - `ResidualAdaa1::process_tanh` panicked on two NaN samples in a row and stayed NaN after one; `process_tanh` and `process_soft_clip` now treat a non-finite sample (and a non-finite `k`) as 0, and a `k` of 0 gives 0 instead of NaN.
  - `Adaa2Taylor::process_hard_clip` spiked far above its clip level on slow signals (3.87 for a 0.9 sine of 50 Hz at 192 kHz), because its divided difference was computed in `f32`. It is computed in `f64` and the output stays within ±1. Its doc now says what the curve is: the cubic `1.5u - 0.5u^3`, not a hard clip.
  - `neural::Model`: the history a `conv1d` layer keeps counts against the 4 million weight budget (a 46 KB file of 200 layers with kernel 64 and dilation 4096 took 202 MiB and ran 8 times slower than real time; it is now refused), a model has at most 256 layers (`neural::MAX_LAYERS`), both checked by `Model::new` as well, and `Model::from_json` refuses a text with more values than a model can hold before parsing it. **A model that loaded before and is over one of these limits is now refused.**
  - A GRU or LSTM whose state overflowed on one huge sample stayed silent until `reset()`; the state is now zeroed and the model plays on.
  - `Compressor` stopped compressing for good after one infinite sample, and `VuMeter` read NaN after one non-finite sample; both skip such samples in their detectors.
  - `Stft::tick`, `process` and `process_in_place` return silence for a channel the transform was not made with, `LoudnessMatch::process` runs to the shortest channel, and `BiquadBank4::set_section` ignores an index past the end, where each panicked.
  - `DynamicEqParams::static_delta_db` with a NaN `range_db` returns 0, and `DiodePair::new` replaces an `is` or `nvt` that is not finite and positive with the 1N4148's, where both panicked in `clamp`.
- LV2 now saves a plugin's own data. The entry answers `state:interface` (listed in the TTL as `lv2:extensionData`): `save` stores the `save_state` chunk as one `atom:Chunk` property (`urn:openplugin:state#chunk`, POD and portable) through the host's `store`, and `restore` hands it to `load_state`. Before, only the control ports were saved, so a chunk (an impulse response loaded through the worker, say) was lost when an LV2 session was reopened. A plugin whose `state_is_parameters_only` is `true` stores nothing; its control ports remain its state, as before. A block that starts during a `save` passes its input through, as in the CLAP entry.

## [1.0.0-beta] - 2026-11-16

Commits `v0.4.0-beta` to the commit that sets the version to 1.0.0-beta. The SDK becomes 1.0 Beta: the roadmap's 0.5 (a dependable editor layer), 0.6 (every format carries everything) and 0.7 (host integration and editor polish) are all done, the last of 0.7 being per-note expression (shell ABI 7); 0.5, 0.6 and most of 0.7 shipped in 0.4.0-beta, and this release completes them. The workspace now builds and is tested on Linux and Windows as well as macOS (roadmap W1 to W4 in [docs/ROADMAP_WINDOWS_LINUX.md](docs/ROADMAP_WINDOWS_LINUX.md)): an X11 editor view with CLAP `gui` and LV2 `ui:X11UI` on Linux; an HWND editor view with UI Automation, CLAP `gui`, LV2 `ui:WindowsUI`, the VST3 and AAX shells and packaging on Windows; and CI on all three systems. The API is not frozen yet: the remaining 1.0 work is listed in [docs/ROADMAP.md](docs/ROADMAP.md).
### Changed

- `openplugin-port` builds on Linux. Its system calls are one file per system (`src/sys/macos.rs`, `linux.rs`, `windows.rs`) behind one switch in `src/sys/mod.rs`; the macOS file is the 0.4.0-beta code unchanged. On Linux the VST3 probes load `<name>.vst3/Contents/<arch>-linux/<name>.so` and call `ModuleEntry`, Audio Unit calls return "Audio Units are macOS-only", and the tests find the example library by the platform's library name. Windows has a placeholder that compiles and reports that loading plug-ins is not supported yet. A failed VST3 entry point now reads "the module entry point returned false" (was "bundleEntry returned false"). `openplugin-testing` links its examples test on Linux with `--allow-multiple-definition`, because two example plug-ins each export `clap_entry`.
- New `docs/PLATFORMS.md`: platform code lives in files of its own, and work for one platform edits only that platform's files; and a `CLAUDE.md` with the repo's rules for coding agents.

LV2: MPE through the atom MIDI input; `lv2::instance_state` is public. Shell ABI 7 (`op_shell.h`, [docs/SHELL.md](docs/SHELL.md#per-note-expression-abi-7)): event kinds `OP_EVENT_NOTE_ON_ID`, `OP_EVENT_NOTE_OFF_ID` and `OP_EVENT_NOTE_EXPRESSION`, and `op_shell_expressions`, `op_shell_expression_info`, `op_shell_expression_format`, `op_shell_expression_parse`. DSP: `NoteExpressions` (per-voice expression and `MOD_SLOTS` modulation values, ramped linearly, taken at once before the voice's first sample), `Polyphony::note_on_ref`, `note_off_ref`, `matching` and `note_ref`, and `VoiceAllocator::note_on_ref`, `note_off_ref`, `matching`, `note_expression`, `poly_modulation` and `set_expression_smoothing` (5 ms by default); `Voice::note_ref`, `expression`, `modulation` and `expressions`. `examples/expression_synth` (Expression Synth, eight voices, `publish = false`) and its proofs through CLAP, LV2 and the shell ABI with negative controls, hostile input and a counting allocator, and the native `vst3_expression_proof` (the VST3 shell over the synth, the controller's note expression info read back, and pressure, brightness and tuning for one note id measured in the audio with the Goertzel algorithm). Not checked in a DAW.

### Changed

- Shell ABI 7. A shell built from this `op_shell.h` refuses a library older than ABI 7, as for every ABI version. The VST3 shell sends notes as `OP_EVENT_NOTE_ON_ID` / `OP_EVENT_NOTE_OFF_ID`; the library hands them to `Plugin::note_on_ref` / `note_off_ref`, whose defaults call the methods the plain kinds called, so a plugin that does not override them hears the same notes. A stand-in library written against an older header that recognises only `OP_EVENT_NOTE_ON` / `OFF` would no longer see VST3 notes; the SDK's own stand-ins are updated.
- `Voice::pitch` and `Voice::hz` (`openplugin_dsp::voice_alloc`) include the voice's tuning expression, which is 0 unless a host sends one. `VoiceAllocator`'s rule 1 (the same note held is retriggered) also needs the same channel when both the voice and the new note have one, so MPE notes of one key on two channels get two voices; a plain `note_on` has no channel and behaves as before.

### Fixed

- Denormals are flushed around every audio-thread call into the plugin, in every format. CLAP `process`, `params.flush` and `reset`, LV2 `run`, and the shell ABI's `process`, `process_events`, `reset` and `midi_out` (the VST3, Audio Unit and AAX shells; the Rust `FfiInstance::process_*` calls go through the same gate) set flush-to-zero for the duration of the call (`FPCR.FZ` on aarch64; `MXCSR` FTZ and DAZ on x86_64; on 32-bit x86 with SSE, DAZ only where `MXCSR_MASK` has it; nothing elsewhere) and restore the host's own floating-point control word afterwards, also when the plugin panics. - `openplugin_dri::DesignEditor`: an editor built from a GoodLookin design CSV, each row bound to a parameter by id; `examples/design_editor`.

- `openplugin_core::worker` (`loader`, `Loader`, `Slot`): load impulse responses, samples and tables on a background thread and swap them into `process` with no lock and no allocation. Old values are returned to the worker and dropped off the audio thread; all queues are bounded and a full job queue returns `QueueFull`. Documented in `docs/ARCHITECTURE.md`.
- `docs/ROADMAP.md` for macOS to 1.0 and `docs/ROADMAP_WINDOWS_LINUX.md`.
- Format parity test, `scripts/format_parity/run.sh` (`docs/FORMAT_PARITY.md`): one input and one parameter automation, with changes mid-block, rendered by the Rust plugin directly and through the built CLAP, LV2, VST3, Audio Unit and AAX entries of `examples/editor`; every output must match sample for sample within 1e-6 (measured difference 0 in every format). Negative controls: VST3, Audio Unit and AAX shells built with a deliberate gain error (test builds only, `-DOP_FORMAT_PARITY=ON`) and a reference with the automation one frame late must fail. A `format-parity` CI job runs everything but AAX, which runs locally.
- `openplugin_dsp::Dither`: RPDF and TPDF dither to 8..=24 bits, first-order and designed order 9 perceptual noise shaping at any sample rate (designed from Terhardt's threshold of hearing; no published coefficient table is reproduced), per-channel seedable PCG32 noise, auto-blank on digital silence, and `i16`/`i24`/`i32` output helpers. `pcm::f32_to_i24` and `i24_to_f32`. New `docs/DSP_COOKBOOK.md` with the dither recipe.
- `openplugin-port null <original> <port>`, the null test of the porting toolkit (porting task 4): renders an original plugin and its port (CLAP, VST3 or Audio Unit, each loaded by path in a child process with a timeout, nothing installed) through the same input and parameter automation, aligns them by their reported latencies, and reports per channel the maximum and RMS difference, the first differing sample with both values and the count over `--tolerance`; exit code 1 over tolerance, 3 when a plugin crashes, hangs or will not load. Inputs: sine sweep, noise, impulses, silence then burst, or an 8/16/24/32-bit integer or float WAV file (own reader, no dependency). Automation is `frame:param=value` in plain values by parameter id or name, with `--param-map` for ports whose ids differ and `openplugin-port param-map` to generate one from scanner manifests. `--save` writes both renders and the difference as WAV files. Proven: the SDK's example built twice nulls with difference 0 through CLAP, VST3 and Audio Unit; a port changed by a test-only hook fails with the first differing sample reported; a plugin reporting 37 samples of latency is aligned; a crash or hang in one plugin fails cleanly. Described in `docs/PORTING.md`.
- `openplugin-port`, a new crate and binary, the first part of the porting toolkit: `openplugin-port scan <plugin>` loads an existing CLAP, VST3 or Audio Unit (each in a child process, with a timeout, so a crashing plugin cannot take the scanner down) and reads an AAX bundle's ids from its page table. It writes a versioned JSON manifest (ids, buses, latency, tail, and every parameter's id, name, range, default, step count, flags and value strings) and a Rust snippet with a `ParamInfo` table, a `PluginInfo` and the build settings, with `TODO` marks for identity the SDK cannot pin yet. Described in `docs/PORTING.md`.
- `openplugin_dsp::FdnReverb`, `PlateReverb` and `EarlyReflections`: reverb building blocks, wet-only, stereo, allocation-free after `new`, NaN- and denormal-safe, stable at every setting. `FdnReverb` is a Jot-Chaigne feedback delay network of 8 or 16 prime-length lines (scaled by size and the real sample rate), Householder or Hadamard feedback, per-line absorption from the decay time at three frequencies by Jot's rule, allpass-interpolated delay modulation, pre-delay, width and freeze. `PlateReverb` is Dattorro's plate topology with the paper's 29761 Hz delay lengths rescaled to the real rate. `EarlyReflections` is a panned tapped delay with five patterns or up to 32 custom taps. Proofs in `crates/openplugin-dsp/tests/`: decay time by Schroeder backward integration within 3.1 % (FDN) and 3.6 % (plate) of the setting at 44.1, 48 and 96 kHz, bounded output over long noise runs at extreme size, decay and freeze, echo density, stereo decorrelation, no allocation, and a test plugin reporting its tail through the `Plugin` trait. Recipe in `docs/DSP_COOKBOOK.md`.
- `openplugin_dsp::simd`: vectorised kernels with run-time selected paths (aarch64 NEON; x86_64 SSE2 and AVX+FMA chosen with `is_x86_feature_detected!`; scalar fallback), no SIMD crate, `core::arch` only, Rust 1.85. `Kernels::detect()` returns a table of function pointers: `gain`, `scale`, `mix_add`, `crossfade`, `cmac_interleaved` / `cmac_split` / `cmac_complex` (the `Complex<f32>` layout `partitioned.rs` uses), `fir` (reversed taps over a history buffer, any tap count), `dot`, `matvec` (row-major, optional bias), and `BiquadBank4` (a biquad cascade over four channels in the four lanes of a register, interleaved or planar). Every kernel has a public scalar twin in `simd::scalar`; gain, mix, crossfade and the biquad bank are bit-identical on every path, the others bit-identical on SSE2 and within the last bit on the FMA paths (bound `n * EPSILON * sum|terms|`). Measured on Apple Silicon with `--release`: `fir` 6.7x, `dot` 6.7x, `matvec` 7.9x, the biquad bank 4.1x, `crossfade` 2.2x; gain, mix and complex multiply-accumulate 1.0x (the compiler already vectorises them). Under Rosetta the SSE2 path gives 6 to 9x on the reductions and the FIR; Rosetta reports no AVX/FMA, so the AVX path is compiled and its generic logic tested through an eight-lane emulation, but not run on real x86. No allocation (`tests/simd_no_alloc.rs`). Existing modules are unchanged; adopting the kernels in `partitioned.rs` and `neural.rs` is a follow-up. See `docs/DSP_COOKBOOK.md` (Vectorised kernels) and `docs/PERFORMANCE.md`.
- Parameter groups (0.6 task 6). `ParamInfo::with_group("Filter/Envelope")` lists a parameter under a group: names separated by `/`, outermost first, `""` (the default) for the top level. `check_group` defines a valid path (no empty name, no name starting or ending with a space, no control character, at most `GROUP_MAX_BYTES` 255), `groups_valid` checks a parameter table at build time, `ParamInfo::host_group` and `group_names` give what hosts are shown (an invalid path is the top level), and `group_paths`, `group_parent` and `group_name` walk the tree. The conformance kit fails `param_fuzz` for an invalid path. CLAP sets `clap_param_info.module` to the path; LV2 writes one `pg:Group` per path and parent (`pg:subGroupOf` for nesting) and `pg:group` on each grouped control port; the VST3 controller offers `IUnitInfo` with one unit per path, nested by path, and sets `ParameterInfo::unitId`; the Audio Unit puts each group in a clump (`kAudioUnitParameterFlag_HasClump`) and names it by the whole path through `kAudioUnitProperty_ParameterClumpName`; the AAX page table (`-DOP_AAX_PAGES=ON`) keeps each group on one control surface page where it fits. A plugin without groups is described exactly as before in every format (no `IUnitInfo`, no clumps, no `pg:` in the TTL, an empty module). Shell ABI 5: `op_shell_param_group(index, buf, cap)`; `OP_SHELL_ABI` is 5 (the Audio Unit proof's stand-in plugins moved to 5, 6 and 2). `examples/editor` puts Gain in `Output` and Warm in `Output/Colour`. Proven by core, ffi, CLAP and LV2 tests (`lv2_validate`, and lilv's `lv2info` reading each port's group), `vst3_proof`, `vst3_track_proof`, `au_proof`, `au_text_proof` and the new `aax_pages_proof`.

### Changed

- `examples/editor` is called "Example Gain", like its bundles; hosts showed the plug-in as "Editor Gain" while the bundle was "Example Gain". Only the displayed name changes: the CLAP, VST3, Audio Unit and AAX identifiers are the same, so saved sessions still find it.
- **Breaking (struct literals only).** `ParamInfo` gains the public field `group` (parameter groups), as it gained `steps` and `flags` in 0.1.1: a plugin that builds `ParamInfo` with a struct literal must add `group: ""`. `ParamInfo::new` and the builders are unchanged, so plugins that use them build as before. The field is serialized only when it is not empty.
- **Breaking (LV2 port indices).** Indices after the parameters are new: every LV2 plugin gains a `freewheel` control port at `first_param + parameter count`, and a plugin whose `note_ports()` has `input` (the default) or `output` gains atom ports after it, then sidechain ports. Ports 0 to 3 and the parameters of an effect keep their indices. An LV2 instrument no longer has audio inputs: its outputs are ports 0 and 1 and its parameters start at port 2 (`lv2::AUDIO_PORTS` stays 4, the effect value; use `lv2::PortMap::first_param`). Hosts that saved state by port symbol or by effect index are unaffected; a plugin with note ports now lists `urid:map` as a required feature.
- VST3 applies parameter changes and the bypass crossfade at their sample offset instead of at the start of the block.
- Audio Unit bypass no longer resets the plugin when it ends; the plugin keeps running and the dry signal is delayed by the reported latency (the base class copied the input with no delay).
- CLAP saves and loads beside `process` safely: a gate for plugins with a chunk, the parameter plane for parameter-only plugins.
- The native build signs each shell bundle again (ad hoc) after its post-build copies, so the bundles verify and the Audio Unit registers.
- Unused dependencies removed: `log` and `serde_json` from core, `serde` and `log` from dsp, `serde` from dri, `cpal` and `raw-window-handle` from targets. The `standalone` feature no longer pulls `cpal`.
- `FfiInstance` guards the plugin object with a gate so that saving and loading a session is safe beside `process`. A block that starts while a state call holds the plugin passes the input through dry. This is behaviour, not a signature change, except for the additions above.

### Fixed

- `openplugin_dsp::PlateReverb` now follows its source, Jon Dattorro, "Effect Design, Part 1: Reverberator and Other Filters" (J. Audio Eng. Soc. 45(9), 1997), which it had been written from memory of. Compared with the paper's figure 1 and tables 1 and 2, the delay lengths, the stage order, the fourteen output taps and their signs, the 0.6 tap gain, the decay diffusion 2 rule and the excursion were right; all eight diffusers had the sign of their coefficient reversed (the input and decay diffusion 2 lattices are `w = x - g z`, `y = z + g w`, and decay diffusion 1 the reverse), the two modulation oscillators were 1.5 rad apart instead of in quadrature. **The sound of the plate changes**; the API does not. Added: `set_decay`, `set_damping`, `set_bandwidth` and `set_paper_defaults` (the paper's coefficients), `decay`, `decay_diffusion_2`, `damping`, `bandwidth`, `rt60`, and `geometry()` with `plate::{PlateGeometry, PlateTap, PlateLine}`. `tests/plate_paper.rs` pins the code to the paper: lengths and taps at 29761 Hz and scaled at 44.1, 48, 96 and 192 kHz, the impulse response against table 2, decay time against the coefficient (0 to 13 % longer than `-3 T / (4 log10 decay)`; `set_rt60` within 4.3 % from 1 s to 10 s with the modulation off and 5.0 % at the default modulation, broadband), echo density, interchannel correlation within 0.006 of zero, and exact silence without subnormals after a burst. In the 1 kHz octave a 1 s setting now measures 1.10 s (was within 3.6 %). Details in `docs/DSP_COOKBOOK.md`.
- `openplugin_dsp::Ppm` reads tone bursts as the public PPM requirements specify. Type II (`Ebu`, `Bbc`) is checked against EBU Tech 3205-E table 2 with its tolerances at 44.1, 48, 96 and 192 kHz: 100 ms -0.06 dB, 10 ms -2.0, 5 ms -3.8, 1.5 ms -9.1 to -9.2, 0.5 ms -15.9 to -16.6 (before: -2.3, -4.8 to -4.9, -11.7 to -12.0, -19.7 to -20.3; three of the four outside tolerance). Type I (`Din`, `Nordic`) reads 10 ms -0.8, 5 ms -2.1, 3 ms -3.8, 0.4 ms -15.2 to -16.4 against -1, -2, -4, -15. The charging constants are derived from the burst table (the integration time is the burst that reads 2 dB low), Type II uses two parallel stages, the reading is calibrated so a steady sine reads its peak (it read 0.18 to 0.28 dB low), and the rectifier is oversampled (8x at 44.1 and 48 kHz, 4x at 96, 2x at 192), so a sine at a quarter of the sample rate no longer reads 3 dB low. **Behaviour change:** `PpmType::Ebu` now returns 24 dB in 2.8 s (Tech 3205-E 3.10) instead of Type I's 20 dB in 1.7 s, and `PpmType::return_time` reports it; a square wave or DC reads up to 0.23 dB above its peak; the reading lags by 8 samples; `Ppm` is larger (about 650 bytes, still `Copy`, no allocation). New: `Ppm::oversampling()`. The requirements, sources, derivation and measurements are in the cookbook under "PPM ballistics".
- The Audio Unit shell did not select layout 0 on a new engine (it skipped `op_shell_set_layout` when the engine already reported the index, which a new engine does without having been prepared for it), so a plugin whose first layout is not its own default, such as one listing mono first, ran with the wrong layout. `Initialize` now always selects it; the one-channel engine of a plugin with no mono layout is unchanged. Found by `au_roles_proof`.
- `openplugin_dsp::Limiter` and `TruePeakClipper` hold their true-peak ceiling on full-band material. The limiter's detector was one 16-tap interpolator, which reads energy near Nyquist up to 2.6 dB lower than a long reconstruction filter does, so full-band white noise and hard-clipped transients came out up to 2.1 dB over the ceiling (the cookbook said 1.7). The detector now evaluates three filters and takes the largest reading: a Hann-windowed sinc of 48 samples each side at 8 points per sample with a sinusoidal fit of the crest, the 4x filter of `TruePeakMeter`, and the taps of `TruePeak::new`. In true-peak mode the limiter also aims `4.5 / lookahead samples` dB under the ceiling (0.06 dB at 1.5 ms and 48 kHz; new `Limiter::margin_db()`), because a gain applied per sample differs from a gain on the reconstructed waveform by up to that much on such material. Measured in the new `tests/true_peak_ceiling.rs` (white and pink noise, hard squares, a sweep to Nyquist, impulses, hard-clipped drum hits, the fs/4 tone; 44.1, 48, 96 and 192 kHz; ceilings -1 and -6 dBFS; an independent 16x reference and `TruePeakMeter`): the worst reading is 0.011 dB under the ceiling for the limiter (it was 1.99 dB over) and 0.017 dB under for the clipper (it was 1.35 dB over); the tests assert at most +0.1 dB. A reconstruction filter that is none of the three can still read full-band noise a few tenths of a dB higher (0.14 dB for a 24-sample sinc, 0.42 dB for a 200-sample one; they read 1.49 and 2.20 dB before). **Latency changes**: `Limiter::latency_samples()` is now the lookahead plus 48 samples (it was plus 9), and `TruePeakClipper::latency_samples()` grows by the same 39 (160 at 48 kHz, was 121); plugins that report these values need no change, sessions see the new delay. CPU on an M1 Max: 69 to 85 ns per sample and channel for the limiter (61 to 72 before), the clipper within 2 % of before (`tests/limiter_bench.rs`, ignored by default). `Limiter::set_true_peak(false)` now measures the sample that is leaving the delay line (it measured the one entering it, 9 samples before that sample's gain was due, so with a 1 ms release a lone peak came out 2.6 dB over the ceiling; test `sample_peak_mode_holds_the_sample_ceiling_with_the_fastest_release`). `TruePeak` is unchanged.

- The type-in field could not be committed in Pro Tools, which takes Return and keypad Enter for its own commands before the field sees them. While the field is open the Cocoa view now holds an `NSEvent` local key-down monitor that takes Return (36), keypad Enter (76) and Escape (53) when the field's own editor has the keyboard (Return and Enter commit, Escape cancels, the event is swallowed; every other key passes), and removes it when the field closes, the view leaves its window or the view is dropped. Losing focus (a click elsewhere, the window resigning key, the view leaving its window) now commits valid text instead of cancelling; invalid text is discarded silently; Escape still cancels. `Editor::take_text_edit` and `text_edit_cancel` docs updated. New `openplugin_dri::cocoa::{field_key, FieldKey, key_monitor_count}`. Proven by main-thread tests (`typing` in `example-editor` and `example-design-editor`: Return, Enter and Escape through `-[NSApplication sendEvent:]`, monitor count back to zero after close, removal and drop); not yet re-tested in Pro Tools.
- `save_bytes` / `load_bytes` raced with `process` (fixed by the gate above), and so did CLAP's `state.save` / `state.load`.
- VST3 `setState` applied values while it was still reading them, so a bad state left them half-applied; it now validates first.
- The shell bundles' signatures were broken by the post-build copies ("code has no resources but signature indicates they must be present").
- AAX bypass copied the dry signal without the reported latency; it is now delayed by the reported latency like VST3 and the Audio Unit.
