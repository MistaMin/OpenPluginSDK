# Changelog

All notable changes to OpenPluginSDK are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are described in [docs/VERSIONING.md](docs/VERSIONING.md).

Entries describe what changes for someone writing a plugin with the SDK, and are written from the git history. Each release names its commit range. Only `v0.1.0-beta.1` is tagged; the later releases are identified by the commit that bumped the version in `Cargo.toml`. Breaking changes are marked **Breaking**.

Before 1.0 the SDK does not promise compatibility between releases: any release may break. Breaking changes are listed under Changed or Removed and marked.

## [Unreleased]

Everything after the 0.3.1 Beta release commit `a708cac`: the 0.4 work on macOS format conformance and the first 0.5 and 1.0 tasks.

### Added

- `openplugin_dsp` modulation and delay blocks: `ModDelay` (a delay line read at a fractional, per-sample delay, sized once, with `Interpolation::{Linear, Hermite, Lagrange(N), Thiran(N)}` after Laakso et al. 1996, "Splitting the Unit Delay"; `phase_delay`, `group_delay` and `frequency_response` give the theory), `Glide` (delay smoother), `Lfo` (sine, triangle, saw, square, sample-and-hold, smoothed random; free-running or locked to `Transport::quarter_notes` by `NoteDivision` or quarter-note length, so it re-aligns after a host jump or tempo change), and `Chorus`, `Flanger` (feedback, optional through-zero) and `Phaser` (cascaded first-order allpasses with feedback). Allocation-free after construction, denormal-safe, panic-free, non-finite input treated as 0. Proven by tests: delay against theory at several fractions, click-free swept sines, LFO lock across jumps and tempo changes (error 6e-8), phaser notches within 2 cents of theory, a no-allocation test, and `openplugin-testing`'s conformance kit on a plugin built from `Chorus`. Recipes in `docs/DSP_COOKBOOK.md`.
- Shell ABI 3: `op_shell_param_format(index, plain, buf, cap)` and `op_shell_param_parse(index, text, out_plain)` hand the plugin's own parameter text (`ParamInfo::format` and `parse`) across the C ABI, UTF-8, message thread, cut on a character boundary, with null and invalid input refused. `OP_SHELL_ABI` is 3. The VST3 shell uses them for `toString` and `fromString`, so a host shows Gain as `6.0 dB` instead of the normalized `0.6250` and reads typed values as the plugin does; the bypass parameter reads `Off` and `On`. Audio Unit and AAX will use them in a follow-up. Found by the REAPER host test (`docs/HOST_TESTS.md`, finding 1).
- `docs/PERFORMANCE.md` and `docs/STABILITY.md`, the guides for plugin developers, and `examples/perf_guide` (workspace member `example-perf-guide`) that holds every measurement they quote. The performance guide covers the real-time rules and how the conformance kit checks them, denormals, block-rate against sample-rate work, smoothing cost, structure of arrays, helping the compiler vectorise, build settings, fast `tanh`/`exp`/`sin` with measured maximum error, oversampling cost, `f32` against `f64`, and measuring with the bench harness and Instruments. The stability guide covers filter topologies under modulation, `f64` state, the NaN/infinity/denormal policy of each SDK filter, panics and the format boundary, thread rules for state, editor and audio, host behaviours to survive, soak and fuzz testing with the kit, and the bugs the kit found in the SDK's own examples. Each performance claim has a before/after benchmark timed by `openplugin_testing::bench` and a test that the two compute the same thing; each stability rule links to the SDK test that enforces it. The guides record two findings in the SDK: the CLAP and LV2 entries have no `catch_unwind` (the shell ABI has), and `Biquad::configure` does not reject a NaN parameter (the filter then outputs silence until configured again). Neither is changed here.
- Universal binaries, proven. `scripts/build_plugin.sh --archs universal` on `examples/editor` (CLAP, LV2, VST3, Audio Unit, AAX) needed no change to build: every bundle binary lists `x86_64 arm64`. The script now checks this at the end (`architectures (...)` per binary; a binary missing a slice fails the run). The x86_64 slice was run under Rosetta on an Apple Silicon Mac: all 18 native ctest proofs (VST3, Audio Unit, AAX), the format parity test (CLAP, LV2, VST3, Audio Unit, AAX, with the negative and timing controls) and `clap-validator` built for x86_64 passed, as did the arm64 slice. `scripts/format_parity/run.sh --arch x86_64` builds and runs the parity test for Intel (under `arch -x86_64` on Apple Silicon). A CI job, `universal`, repeats it on the arm64 runner without AAX. Details in `docs/BUILD.md`.
- VST3 parity on shell ABI 2 (`native/vst3`, described in `docs/SHELL.md`, "VST3 on ABI 2"). The shell processes through `op_shell_process_events`: parameter changes are sample-offset events (still sample-accurate; bypass still crossfades). A plugin with a note input gets an event input bus (`kNoteOnEvent`, `kNoteOffEvent`, `kPolyPressureEvent`, legacy MIDI CC events) and `IMidiMapping` onto 16 x 130 hidden parameters for CCs, channel pressure and pitch bend; a plugin with a note output gets an event output bus fed from `op_shell_midi_out`. `ProcessContext` reaches the plugin as `OpTransport`. A layout with a sidechain gets an aux input bus (inactive by default) passed as the sidechain. `setBusArrangements` and `getBusArrangement` follow the plugin's layouts (mono, stereo, 5.1, 7.1, 7.1.4, ambisonics to 4th order where the plugin offers them) and the shell reorders VST3's speaker order to the SDK's canonical order at the edge. `kOffline` calls `op_shell_set_offline`. The category comes from `op_shell_kind()` (`Instrument|Synth`, `Fx`). The ABI check is now "library version at least `OP_SHELL_ABI`". Proofs: `vst3_events_proof` over three stand-in plugins (`native/vst3/events_stub.cpp`), `vst3_noalloc_events_proof`, the parity fault control for the events entry point (`scripts/format_parity/native/parity_fault_events.cpp`); pluginval 1.0.4 at strictness 10 passes on the example and both stand-ins. Known gap: VST3 parameter text shows the normalized value because the shell ABI has no value format or parse call.
- `openplugin_dsp::{windows, stft, spectrum}`: `WindowKind` (rectangular, Hann, Hamming, Blackman, four-term Blackman-Harris, flat-top, Kaiser with `beta`, square-root Hann) with `coherent_gain` and `enbw_bins`, checked against Harris 1978. `Stft` is a multichannel STFT frame processor with overlap-add resynthesis: power-of-two frame, any hop, analysis and synthesis windows, `check_ola` (the constant-overlap-add or weighted-overlap-add error of a window/hop pair), latency equal to the frame for `Plugin::latency`, any host block size including 1, and a `SpectralProcessor` callback that edits bins `0..=frame/2` in place. `SpectrumAnalyzer` publishes calibrated dB magnitudes (averaged, with peak hold) through a wait-free seqlock feed to a `SpectrumReader` on the UI thread; `log_frequency_bins` maps them to a log axis. No allocation in `process`; proofs in `tests/stft_identity.rs` and `tests/spectral_no_alloc.rs`.
- LV2 `worker` extension: when the host offers `worker:schedule`, loaders made with `openplugin_core::worker` run their jobs on the host's worker thread (`worker:interface` `work`, `work_response`, `end_run` through `extension_data`), scheduled from `run` without allocating; without the feature they keep their own thread. The TTL lists `work:schedule` as an optional feature and `work:interface` as extension data. Plugins need no LV2 code. New in `openplugin_core::worker`: the `Executor`, `Task` and `Waker` traits, `Step` and `with_executor` (additive; the existing API is unchanged). `lv2::worker_stats` and `lv2::WorkerStats` report what the bridge did. Proven in `tests/lv2_worker.rs` and `tests/lv2_worker_no_alloc.rs`; `lv2_validate` reports 0 errors.
- Accessibility on macOS. Additive `Editor` methods `accessibility_nodes`, `accessibility_action` and `accessibility_focus` (defaults: no nodes, no action), with `AccessNode`, `AccessRole` and `AccessAction` in `openplugin_core::editor`. `ControlSet` (so `DesignEditor` and `examples/editor`) lists every control with its parameter name, `ParamInfo::format` text and a role (slider for knobs, faders and key banks, check box for toggles, button for momentary buttons), and answers VoiceOver increment (5% of the travel, or one position for stepped parameters), decrement and press with the same begin, perform, end gestures as the mouse. The Cocoa view exposes the nodes as `NSAccessibilityElement` children with screen frames, follows keyboard focus, and posts value-changed, focus-changed and layout-changed notifications, including for host automation. Proven by main-thread tests that read the tree and drive the actions (`examples/editor/tests/a11y.rs`, `examples/design_editor/tests/a11y.rs`); not yet checked by hand with VoiceOver.
- `openplugin_dsp::utility`: mid/side, stereo width, pan laws (-3 dB constant power, exactly -4.5 dB, -6 dB linear) for mono-to-stereo pan and stereo balance, per-channel polarity, a smoothed dB `Gain` and `Panner` (core one-pole), and `DenormalGuard`, an RAII flush-to-zero for the current thread (aarch64 `FPCR.FZ`, x86_64 `MXCSR` FTZ and DAZ through inline assembly, restored on drop, no-op elsewhere).
- Metering, all allocation-free: `TruePeakMeter` (a multichannel meter beside the limiter's `TruePeak` detector; BS.1770-4 Annex 2 oversampling, 4x/2x/1x by rate, with hold; EBU Tech 3341 signals 15 to 19 within +0.2/-0.4 dB), `Ppm` with the ballistics of EBU (IEC 60268-10 Type IIb), DIN (Type I), Nordic and BBC (Type IIa) and their scales, `KMeter` for K-12, K-14 and K-20 after Katz, `VuIec` (IEC 60268-17: 99 % in 300 ms, 1.3 % overshoot; the existing `VuMeter` is a one-pole and does not meet it, and is unchanged), and `scope_feed`, a lock-free correlation and goniometer feed (writer never blocks or allocates; reader on the editor thread) built on the core `Seqlock`.
- Loudness, additively: loudness range (EBU Tech 3342), maximum momentary and short-term, start/pause of the integrated value, BS.1770-4 channel weights by channel role for surround (`Loudness::for_layout`, `with_roles`, `bs1770_weight`; LFE excluded), `EbuMeter` (EBU Mode of Tech 3341 with the +9 and +18 scales, LU and LUFS readouts and true peak) and named `Target`s (EBU R 128, ATSC A/85). `Loudness` now evaluates every 10 ms internally; integrated values are unchanged. Proven against EBU Tech 3341 v4 cases 1 to 6 and 9 to 14 and Tech 3342 v4 cases 1 to 4 (`tests/ebu_conformance.rs`); the authentic-programme cases are not covered.
- `openplugin_dsp::downmix`: `Downmix` folds any SDK layout with a speaker map (Mono, Stereo, LCR, Quad, 5.0, 5.1, 6.1, 7.1, 7.1.4) to stereo or mono by channel role, and `Upmix` spreads stereo to any layout. 5.x to stereo follows ITU-R BS.775-3 and ATSC A/52 (centre and surrounds at -3 dB, LFE dropped). 6.1, 7.1 and height folds are documented choices, not standards. Centre, surround, height and LFE levels in dB at run time, optional peak normalisation, a precomputed matrix, and no allocation in `process`.
- Shell ABI 2 (`OP_SHELL_ABI` is 2; `op_shell_abi_version()` reports the library's). Additive: `op_shell_process` is unchanged and now calls `op_shell_process_events`, which carries sample-offset events (note on, note off, raw MIDI, parameter changes, delivered sample-accurately as in CLAP), a transport struct, an optional sidechain and multichannel pointer arrays. `op_shell_midi_out` hands the plugin's MIDI output to a caller buffer. `op_shell_layout_count`, `op_shell_layout` (each bus's kind and canonical channel roles), `op_shell_set_layout` and `op_shell_layout_selected` query and select layouts. `op_shell_set_offline`, `op_shell_kind` and `op_shell_note_ports` (derived from existing plugin data) complete it. The path is allocation-free and refuses hostile input. Channel order across the ABI is canonical; shells reorder. Versioning rule and details in `docs/SHELL.md`. No VST3, Audio Unit or AAX source changed.
- LV2 parity with CLAP: an `atom:Sequence` input when `note_ports().input` (`midi:MidiEvent` delivered at its frame offset through `note_on_channel`, `note_off` and `midi::deliver`; `time:Position` mapped onto `Transport`), an `atom:Sequence` MIDI output from `pull_midi` when `note_ports().output`, one `lv2:isSideChain` audio input per sidechain channel (`process_buses`), an `lv2:freeWheeling` control port wired to `set_offline`, and `lv2:InstrumentPlugin` with no main audio input for an instrument. `lv2::PortMap` and `lv2::layout_of` describe the layout. Proven through the exported descriptor (`tests/lv2_ports.rs`, `lv2_atoms_hostile.rs`, `lv2_ports_no_alloc.rs`); `lv2_validate` reports 0 errors on the generated files, and `lv2apply` still renders the example.
- `openplugin_dsp::partitioned` (`LongConvolver`, `ConvolverConfig`, `ConvolutionIr`, `Layout`): long convolution for impulses of seconds at 44.1 to 192 kHz. Uniformly or non-uniformly partitioned in the frequency domain (default stage sizes 64, 512, 4096, after Gardner 1995), a direct-form head so there is no added latency, mono, stereo and true-stereo (`LL`, `LR`, `RL`, `RR`), any host block size, allocation-free and panic-free `process`, impulses prepared off the audio thread and handed over through `openplugin_core::worker`. Equal to direct convolution within 3e-7 in the tests; a 3 s impulse at 48 kHz costs about 4 us per 64-sample block. `BlockConvolver` is unchanged. `docs/DSP_COOKBOOK.md` has a Convolution recipe.
- `openplugin-dsp` dynamics (DSP library task 3; recipes in `docs/DSP_COOKBOOK.md`): `EnvelopeFollower` and `Ballistics` (peak and RMS, attack, release and hold, branching and decoupled, linear or log domain, after Giannoulis, Massberg and Reiss 2012); `GainComputer` (compressor, expander, gate; soft knee, ratios up to infinity, range, gate hysteresis); `Dynamics` (any number of channels, `Link::Max` or `Average`, one gain for all channels, external sidechain and a per-sample filter hook for plugging in any `f32 -> f32` filter); `Limiter` (lookahead brickwall with a true-peak ceiling, smooth gain, `latency_samples()` for `Plugin::latency`) and `TruePeak` (BS.1770-4 Annex 2 4x detector and a more accurate 8x one). The old `Compressor` is unchanged. Proofs in `crates/openplugin-dsp/tests/dynamics.rs` (static curves, time constants, hysteresis, linked gain, ceiling against an independent 16x interpolator) and `dynamics_no_alloc.rs`.
- `openplugin-dsp` filters (DSP library task 2), with a "Filters" section in `docs/DSP_COOKBOOK.md`: `Svf` (topology-preserving state-variable filter, nine modes including bell and shelves, safe to modulate every sample); `MatchedBiquad` (Vicanek analog-matched low-pass, high-pass, band-pass, notch, peaking and shelves; the RBJ `Biquad` is unchanged); `Crossover` and `LinkwitzRiley` (LR2, LR4, LR8; 2, 3 and 4 bands; band sum flat within 0.01 dB from 20 Hz to 20 kHz); `Butterworth` (orders 1 to 8), `OnePoleFilter`, `DcBlocker`, `Allpass1` and `Allpass2`. Coefficients follow the real sample rate, nothing allocates, a non-finite input sample is treated as `0.0`, and tails flush to zero. Proofs in `crates/openplugin-dsp/tests/filters.rs` and `filters_no_alloc.rs`.
- `openplugin-dsp` synthesis (DSP library task 7), with a "Synthesis" section in `docs/DSP_COOKBOOK.md`: `BandlimitedOsc` (saw, square, pulse with PWM, triangle; PolyBLEP and PolyBLAMP after Välimäki and Huovilainen 2007 and Välimäki, Pekonen and Nam 2012, B-spline kernels of width 2, 4, 6 or 8 chosen with `BlepOrder`, sample-accurate hard sync); `WavetableSet` and `WavetableOsc` (one octave level per halving of the harmonic count, built by FFT off the audio thread, cubic read); `Adsr`/`Ahdsr` (linear or exponential segments, whole-sample timings that land exactly on the target, retrigger and legato, gate events at block offsets); `WhiteNoise` and `PinkNoise` (a pole/zero ladder recomputed for the real sample rate); `VoiceAllocator<S, N>` (stealing by oldest, quietest or same note, release tails stolen first, mono and legato with a held-key stack, linear glide of exact length, sustain pedal, generic per-voice state); `SincKernel`, `SincPlayer` and `playback_ratio` (Kaiser-windowed sinc, polyphase table, four quality presets, any pitch ratio from 1/64 to 16, loops). Measured: aliased power of the 4-point saw is 27 dB below the naive saw at 5 kHz (44.1 kHz) and each wider order gains about 9 dB; envelope stages exact to the sample at 22.05 to 192 kHz; pink slope -2.99 dB per octave over four decades; resampler stopband -59 to -119 dB. No allocation on the audio path (counting-allocator test), and a test synth built from the blocks passes `openplugin-testing`'s conformance kit. `oscillator.rs` and `voice.rs` are unchanged.
- `openplugin-testing` (dev-dependency; `openplugin::testing` behind the facade's `testing` feature): `conformance(make, Options)` runs a plugin through eight sample rates, eleven block sizes and a random block sequence, silence, DC, noise, sweeps, NaN and infinity bursts and denormals, parameter fuzz at random sample offsets, reset in a tail, state round-trips, every supported layout, offline, hostile transport and notes. It checks allocation (a counting allocator, installed with `openplugin_testing::install_allocator!()`), panics, NaN, infinity and denormals, output bound, latency, tail, reset and state, and returns a deterministic, seeded report that names the first failing case. Lock detection is not possible in user space and is reported as skipped. `bench::bench` and `bench::cli` measure CPU time per block as a fraction of real time (median and p99) with a stable text and JSON report and `compare` for two commits. See `docs/TESTING_PLUGINS.md`.
- Audio Unit parity on shell ABI 2 (`native/au`). The shell renders through `op_shell_process_events` and builds `aufx`, `aumu` (`MusicDeviceBase`) or `aumf` (`AUMIDIEffectBase`) from one source: `-DOP_AU_TYPE=auto` (default) asks the plugin's `op_shell_kind` at configure time (an effect stays `aufx`; say `-DOP_AU_TYPE=aumf` for a music effect). MIDI in through `MusicDeviceMIDIEvent` and MIDI out through `kAudioUnitProperty_MIDIOutputCallback`, both at sample offsets; `AudioUnitScheduleParameters` (immediate events, and ramps as 16 frame steps) and `AudioUnitSetParameter` with a buffer offset are sample-accurate parameter events; `HostCallbackInfo` fills `OpTransport`; a second input element is the sidechain; `SupportedNumChannels`, `kAudioUnitProperty_SupportedChannelLayoutTags` and `kAudioUnitProperty_AudioChannelLayout` follow the plugin's layouts (mono, stereo, 5.1 in four tag orders, 6.1, 7.1, 5.1.4 and 7.1.4 in two orders, channel descriptions), reordered to the SDK's canonical channel order at the edge with no copy; `kAudioUnitProperty_OfflineRender` reaches `op_shell_set_offline`. The ABI check is now "library version >= `OP_SHELL_ABI`". Proven by `au_events_proof` (five test components, allocation counted around the render), the existing `au_*` proofs, and the format parity test, where the Audio Unit now takes the automation as scheduled events (difference 0 as before; its negative control still fails). Atmos beds with top-middle or wide channels (5.1.2, 7.1.2, 9.1.6) wait for roles in the layout list. `auval` runs in CI, on installed components only.
- AAX parity on shell ABI 2. The AAX shell calls `op_shell_process_events`: parameter changes from the controls packet are events at the start of the block (AAX packets carry no offset), MIDI from the local input node arrives at its sample offsets and the plugin's MIDI is posted to a local output node when `op_shell_note_ports()` asks for either, the transport is read from a transport node through `AAX_ITransport` (version 1 calls only, no locks) into `OpTransport`, and a layout's sidechain is the side-chain input channel. Stem formats come from `op_shell_layout*`: mono, stereo, LCR, quad, 5.0, 5.1, 6.1, 7.1, 5.1.4, 7.1.4 and first to third order ambisonics, one component and plug-in ID per stem pair; Pro Tools' channel order (L C R Ls Rs LFE for 5.1 and its 7.1 and 7.1.4 forms) is reordered to the canonical order at the edge, by pointer. The plugin category follows `op_shell_kind()` (software generator, MIDI effect or effect). The host's offline-bounce notifications reach `op_shell_set_offline`; AudioSuite is a separate AAX type and is not described. The ABI check is now "library version >= 2". Limits (SysEx and four-byte MIDI not carried, a mono sidechain, no record state, no top-middle Atmos stems, offline untested in Pro Tools) are in `docs/SHELL.md`. New proofs `aax_events_proof` and `aax_describe_proof`; `aax_alloc_latency_proof` covers the new paths; format parity's AAX negative control follows the new call.
- `op_shell_save_state` and `op_shell_load_state` in the shell ABI. They carry the parameters and the plugin's own chunk (`Plugin::save_state` / `load_state`) in one blob, all or nothing. `OP_SHELL_ABI` stays 1; nothing existing changed. The VST3 shell carries the blob in its component state (a trailer after the version 1 fields), the Audio Unit in its class-info dictionary (key `OpenPluginState`), and AAX in state chunk version 2; states written by earlier versions still load.
- `openplugin_ffi::STATE_WAIT` (two seconds) and `FfiInstance::try_save_bytes`, the bounded form of `save_bytes`.
- VST3: a `kIsBypass` host bypass parameter. VST3, the Audio Unit and AAX bypass by delaying the dry signal by the reported latency with a 10 ms crossfade, and the plugin keeps running. CLAP's `PARAM_IS_BYPASS` reaches `Plugin::set_host_bypass`.
- AAX: parameter and plugin state saved as a versioned chunk (corrupt chunks are refused without touching any parameter); the controls packet is sized by the parameter count, so plugins with more than 64 parameters work (proven with 200).
- `scripts/build_plugin.sh`, which builds CLAP, LV2, VST3, Audio Unit and AAX bundles for one plugin, keeps build paths out of the binaries, and signs, notarises and PACE-signs when the environment asks for it. Described in `docs/BUILD.md`.
- `scripts/build_plugin.sh --pkg` and `scripts/make_pkg.sh`: an installer package with one component package per built format (CLAP, LV2, VST3, Audio Unit, AAX under `/Library/...`) and a distribution package in which the user picks the formats. Signed with `INSTALLER_IDENTITY`, notarised and stapled with `NOTARY_PROFILE`; unsigned, with a note, otherwise. `scripts/test_pkg.sh` builds the example and checks every bundle sits at its install path. Described in `docs/BUILD.md`.
- `scripts/aax_validate.sh`, which runs Avid's AAX Validator against the example bundle locally (13 passed, 0 failed, 1 skipped).

- `Plugin::state_is_parameters_only` (default `false`). A plugin that returns `true` saves and loads from the parameter plane without the state gate, in the shells and in CLAP, so a host saving during playback never skips a block. The SDK's examples opt in.
- `openplugin_dri::hit`: a control registry (knobs, faders, toggles, buttons, key banks) that turns mouse input into host gestures, with double-click reset, fine adjustment, wheel and stepped snapping; `Editor::modifiers_changed`.
- `openplugin_dri::DesignEditor`: an editor built from a GoodLookin design CSV, each row bound to a parameter by id; `examples/design_editor`.
- `docs/PUBLISHING.md`, `CHANGELOG.md`, `docs/VERSIONING.md` and `docs/API_REVIEW.md`; crate metadata (authors, homepage, keywords, categories, readme, documentation) inherited by every crate; GoodLookin DRI named by version as well as path.
- `openplugin_core::worker` (`loader`, `Loader`, `Slot`): load impulse responses, samples and tables on a background thread and swap them into `process` with no lock and no allocation. Old values are returned to the worker and dropped off the audio thread; all queues are bounded and a full job queue returns `QueueFull`. Documented in `docs/ARCHITECTURE.md`.
- `docs/ROADMAP.md` for macOS to 1.0 and `docs/ROADMAP_WINDOWS_LINUX.md`.
- Format parity test, `scripts/format_parity/run.sh` (`docs/FORMAT_PARITY.md`): one input and one parameter automation, with changes mid-block, rendered by the Rust plugin directly and through the built CLAP, LV2, VST3, Audio Unit and AAX entries of `examples/editor`; every output must match sample for sample within 1e-6 (measured difference 0 in every format). Negative controls: VST3, Audio Unit and AAX shells built with a deliberate gain error (test builds only, `-DOP_FORMAT_PARITY=ON`) and a reference with the automation one frame late must fail. A `format-parity` CI job runs everything but AAX, which runs locally.

New `docs/DSP_COOKBOOK.md` with the dither recipe.
- `openplugin-port`, a new crate and binary, the first part of the porting toolkit: `openplugin-port scan <plugin>` loads an existing CLAP, VST3 or Audio Unit (each in a child process, with a timeout, so a crashing plugin cannot take the scanner down) and reads an AAX bundle's ids from its page table. It writes a versioned JSON manifest (ids, buses, latency, tail, and every parameter's id, name, range, default, step count, flags and value strings) and a Rust snippet with a `ParamInfo` table, a `PluginInfo` and the build settings, with `TODO` marks for identity the SDK cannot pin yet. Described in `docs/PORTING.md`.
- `openplugin_dsp::FdnReverb`, `PlateReverb` and `EarlyReflections`: reverb building blocks, wet-only, stereo, allocation-free after `new`, NaN- and denormal-safe, stable at every setting. `FdnReverb` is a Jot-Chaigne feedback delay network of 8 or 16 prime-length lines (scaled by size and the real sample rate), Householder or Hadamard feedback, per-line absorption from the decay time at three frequencies by Jot's rule, allpass-interpolated delay modulation, pre-delay, width and freeze. `PlateReverb` is Dattorro's plate topology with the paper's 29761 Hz delay lengths rescaled to the real rate. `EarlyReflections` is a panned tapped delay with five patterns or up to 32 custom taps. Proofs in `crates/openplugin-dsp/tests/`: decay time by Schroeder backward integration within 3.1 % (FDN) and 3.6 % (plate) of the setting at 44.1, 48 and 96 kHz, bounded output over long noise runs at extreme size, decay and freeze, echo density, stereo decorrelation, no allocation, and a test plugin reporting its tail through the `Plugin` trait. Recipe in `docs/DSP_COOKBOOK.md`.

### Changed

- **Breaking (LV2 port indices).** Indices after the parameters are new: every LV2 plugin gains a `freewheel` control port at `first_param + parameter count`, and a plugin whose `note_ports()` has `input` (the default) or `output` gains atom ports after it, then sidechain ports. Ports 0 to 3 and the parameters of an effect keep their indices. An LV2 instrument no longer has audio inputs: its outputs are ports 0 and 1 and its parameters start at port 2 (`lv2::AUDIO_PORTS` stays 4, the effect value; use `lv2::PortMap::first_param`). Hosts that saved state by port symbol or by effect index are unaffected; a plugin with note ports now lists `urid:map` as a required feature.
- VST3 applies parameter changes and the bypass crossfade at their sample offset instead of at the start of the block.
- Audio Unit bypass no longer resets the plugin when it ends; the plugin keeps running and the dry signal is delayed by the reported latency (the base class copied the input with no delay).
- CLAP saves and loads beside `process` safely: a gate for plugins with a chunk, the parameter plane for parameter-only plugins.
- The native build signs each shell bundle again (ad hoc) after its post-build copies, so the bundles verify and the Audio Unit registers.
- Unused dependencies removed: `log` and `serde_json` from core, `serde` and `log` from dsp, `serde` from dri, `cpal` and `raw-window-handle` from targets. The `standalone` feature no longer pulls `cpal`.
- `FfiInstance` guards the plugin object with a gate so that saving and loading a session is safe beside `process`. A block that starts while a state call holds the plugin passes the input through dry. This is behaviour, not a signature change, except for the additions above.

### Fixed

- `save_bytes` / `load_bytes` raced with `process` (fixed by the gate above), and so did CLAP's `state.save` / `state.load`.
- VST3 `setState` applied values while it was still reading them, so a bad state left them half-applied; it now validates first.
- The shell bundles' signatures were broken by the post-build copies ("code has no resources but signature indicates they must be present").
- AAX bypass copied the dry signal without the reported latency; it is now delayed by the reported latency like VST3 and the Audio Unit.

## [0.3.1-beta] - 2026-11-14

Commits `22d4007` to `a708cac`. The hardening release (roadmap 0.3.x). GoodLookin DRI 0.2 rendering, then a pass of hostile-input, allocation and conformance proofs.

### Added

- GoodLookin DRI 0.2 drawing in `openplugin-dri`:
  - `DrawList::knob_tier` and the re-exported `KnobTier` pick the knob tier: lit by default, with the classic and flat tiers still available. A `lit_` or `flat_` prefix on a knob style code picks the tier for one knob.
  - `SceneCanvas`, which rasterises a whole scene into the pixels an `Editor` returns, at the display's backing scale. `SceneCanvas::frame_layered` keeps the static plate as pixels and repaints only the moving parts (18.3 ms to 3.0 ms per frame for the example at 2x, identical pixels).
  - `knob_angle`, the pointer angle for a rotary control.
  - `DrawList` records the faceplate colour so lit knobs reflect it; faders ink their scale for the panel.
- `MIN_SAMPLE_RATE`, `MAX_SAMPLE_RATE` and `sample_rate_supported` in `openplugin-core`, and `effective_rate` in `openplugin-dsp`.
- Tests that ship with the crates: hostile-input suites for CLAP events, LV2 ports, the `op_shell_*` ABI and state loading (NaN, infinity, denormals, oversized blocks, garbage indices); no-allocation tests for CLAP, LV2 and the shell; `tests/low_rates.rs`; shell proofs over `examples/editor` that check parameters, state round trip, tail, latency and bypass for any plugin.
- macOS CI: workspace tests, the main-thread Cocoa test, clippy with warnings as errors, and a minimum-Rust job. GoodLookinDri is pinned to a commit in CI.
- `docs/ROADMAP.md`.

### Changed

- **Breaking (Rust API):** `openplugin_ffi::shell::write_info` and `write_param` are now `unsafe fn` with a `# Safety` contract. The C ABI and its null behaviour are unchanged. `export_shell!` wraps the calls; direct callers must add `unsafe`.
- **Breaking (behaviour):** the accepted sample-rate range is now 1 kHz to 768 kHz in every format bridge (CLAP `activate`, LV2 `instantiate`, `op_shell_create`, `FfiInstance::prepare`). The default of `Plugin::accepts_sample_rate` was 8 kHz to 768 kHz. A plugin can narrow the range but not widen it. `FfiInstance::prepare` returns false outside the range instead of substituting a rate; `FfiInstance::new` still uses 48 kHz for an invalid rate. LV2 `instantiate` still accepts `0.0` (unknown rate) and prepares at 48 kHz.
- **Breaking (behaviour):** the DSP blocks compute for the real rate down to 1 kHz (loudness, K-weighting, `LoudnessMatch`, `SoftBypass`, `Delta`, `GainComp`, `BlockLevel`, `MeterBank`). Before, rates under 8 kHz were treated as invalid, computed as 48 kHz, or rounded up to 8 kHz. `MeterBank::new` no longer refuses low rates.
- **Breaking (appearance):** rotary controls sweep +-0.8 pi (+-144 degrees), the sweep GoodLookin design files use, instead of +-135 degrees. Knobs are drawn in the lit tier by default. `DrawList::commands` now comes from `Scene::lower_basic`, with lit knobs drawn again in the classic tier for hosts without images.
- **Breaking (build):** the workspace is edition 2024 and `rust-version` is 1.85, up from 1.80. Rust 1.85 is the oldest Rust that reads the edition-2024 crates in the dependency tree (`coreaudio-sys` through `cpal`); 1.84 cannot build it. A plugin may stay on edition 2021: the export macros write `#[unsafe(no_mangle)]`, which any edition accepts from Rust 1.82.
- Painting holds a process-wide lock, because GoodLookin DRI keeps the knob scale and floor colour process-wide.
- The `Default` impls for `Compressor` and `VuMeter` exist now (a clippy-driven addition). Targeted lint allows on public drawing and processing functions; no signatures changed.

### Fixed

- Several DSP blocks used 48 kHz or 8 kHz for rates under 8 kHz (see Changed).

## [0.3.0-beta] - 2026-11-14

Commits `06436bc` to `2b1d828`. One editor in every format.

### Added

- The editor contract, `openplugin_core::editor`: `Editor`, `EditorFactory`, `EditorHost`, `EditorState`, `Gesture`, `Frame`, `GestureQueue`, `ValueMirror`. A plugin writes one `Editor` and passes `editor = make_editor` to `export_clap!`, `export_lv2!` and `export_shell!`.
- `openplugin_dri::cocoa::EditorView` and `run_window`: a Rust `NSView` driven through the Objective-C runtime, used by CLAP (`clap.gui`), LV2 (`ui:CocoaUI` with instance access) and the VST3, Audio Unit and AAX shells. macOS only.
- `export_shell!` writes the `op_editor_*` functions in Rust and always exports `op_shell_tail_seconds` (from `Plugin::tail`). A live-instance table guards `op_editor_bind`. An opt-in trace file records what a host does with the shell.
- Shell build options (all off by default, so a plugin without an editor builds as before): `OP_EDITOR` hosts the view in VST3, Audio Unit and AAX; `OP_TAIL` reports the tail in VST3 and Audio Unit; `OP_AAX_PAGES` builds `OpenPluginAAXPages` and writes `<Product>Pages.xml` into the AAX bundle (AAX Validator's page-table tests pass).
- `Plugin::aax_ids` (fixed four-character AAX codes), `Plugin::lv2_uri`, and `AaxIds`.
- LV2: one control port per parameter (hosts could not set any before), `ui:CocoaUI`, and `write_bundle`, `manifest_ttl` and `plugin_ttl` for the bundle files.
- Presets: a `key = value` text format read through `ParamInfo::parse`, `PresetBank`, and `build::embed_files` for `build.rs`.
- `ParamInfo::parse`, the inverse of `ParamInfo::format`; CLAP `text_to_value` reads choice names, On/Off and units through it.
- DSP: `KWeighting` and `Loudness` after ITU-R BS.1770-4 (momentary, short-term, gated integrated), `LoudnessMatch` auto gain, and `Delta`.
- `examples/editor`: one plugin exported in every format, with a test that runs on the main thread and drives the editor through CLAP, LV2 and the shell.
- Copyright holder set to Marcos Quirino Deida; test fixtures and examples use "OpenGrid" as vendor.

### Fixed

- CLAP `state.load` restores the parameter snapshot that `state.save` writes for a plugin without its own state; it returned false before.
- Audio Unit: `reset` runs on the render thread instead of racing it; a failed initialize or render status is kept and logged by the view; parameter names are published as CFStrings.
- AAX: continuous parameters keep the default step count (10001 steps fails AAX Validator).
- Audio Unit reports every failed render (base class errors included) instead of rendering silence without a report.
