# Host shell

## Summary

This is the 0.3.1 Beta host contract. `export_shell!` exports one plugin as a C ABI named `op_shell_*`. A thin native adapter calls that ABI. The same symbols feed VST3, Audio Unit, and AAX. The Rust layouts in `openplugin-targets` are not loadable. The adapters are `native/vst3`, `native/au`, and `native/aax`. The adapters in this release are macOS.

`create` allocates the plugin and its scratch. `set_plain`, `set_normalized`, and `process` do not allocate. The audio thread applies the parameter plane inside `process`. `new` is not used from the audio thread.

The shell is mono or stereo, 32-bit float, and one plugin per binary. It hosts an editor only when the plugin exports the optional editor ABI (see Editor). AAX development IDs are a hash of the plugin id. `Plugin::aax_ids` replaces them with fixed four-character codes, which a release needs. The AAX controls packet is sized from the parameter count; the shell takes up to 4096 parameters.

## Export

```rust
openplugin_targets::export_clap!(EditorGain);
openplugin_targets::export_lv2!(EditorGain);
openplugin_targets::export_shell!(EditorGain);

// With an editor (macOS): the same three, plus `editor = make_editor`.
openplugin_targets::export_shell!(EditorGain, editor = make_editor);
```

The crate type includes `staticlib`. The native build links that archive. It does not sign or copy a plugin into a system folder.

## Allocation

| Call | Thread | Allocates |
|---|---|---|
| `op_shell_info`, `op_shell_param`, `op_shell_to_plain`, `op_shell_to_normalized` | message | no, after the first descriptor read |
| `op_shell_create` | message, while inactive | yes |
| `op_shell_destroy`, `op_shell_reset` | message, while inactive | `destroy` frees |
| `op_shell_set_plain`, `op_shell_set_normalized` | audio | no |
| `op_shell_process` | audio | no |
| `op_shell_save_state`, `op_shell_load_state` | message, any time | yes (the blob) |

`process` copies through scratch allocated in `create`, so an input pointer may be the output pointer. A null right pointer is mono. A block longer than the size passed to `create` fails. The adapters split a host block into that size. The prepared size is at most 65536 frames, and the AAX callback uses 2048.

Class IDs are 16 bytes from a 128-bit mix of the plugin id. VST3 prints them with `FUID::toString`, 32 hex digits. The processor id and the controller id differ. AAX manufacturer, product, mono, and stereo ids are four-byte values from that mix with bit `0x20` set in each byte so none is zero.

## Events, transport, buses and kind (ABI 2)

`op_shell_process` stays as it was and is now `op_shell_process_events` with no events, no sidechain and a stereo (or mono) bus. The new entry point carries everything a note-driven or multi-bus plugin needs, so each C++ shell can map its host's events onto it. Declarations are in `native/include/op_shell.h`; the Rust side is `crates/openplugin-ffi/src/block.rs` and `shell.rs`.

| Call | Thread | Allocates |
|---|---|---|
| `op_shell_abi_version`, `op_shell_kind`, `op_shell_note_ports`, `op_shell_layout_count`, `op_shell_layout` | message | yes (they build a plugin to ask it) |
| `op_shell_set_layout`, `op_shell_layout_selected` | message, before the first block | yes (new scratch) |
| `op_shell_set_offline` | any | no |
| `op_shell_process_events` | audio | no |
| `op_shell_midi_out`, `op_shell_midi_dropped` | audio thread, after the block | no |

### Versioning

`OP_SHELL_ABI` in the header is the ABI version the shell was written for; `op_shell_abi_version()` and `OpShellInfo.abi` are the version of the library. The rule:

- A version only adds: functions, enum values, struct fields at the end of a struct that carries `struct_size`. Nothing is removed, renamed or changed in meaning. Adding anything raises the number (1 was everything up to save/load state, 2 adds this section).
- A shell built against `OP_SHELL_ABI = N` works with any library of version N or higher, and must refuse a library below N (`op_shell_abi_version() < OP_SHELL_ABI`) instead of calling symbols that are missing. The shells that existed before ABI 2 compare `info.abi` for equality; they are built from the same header as the library, so that still holds.
- A change that cannot be additive gets new symbol names (a new prefix), so a mismatch fails at load instead of misbehaving.

### Channel order

ABI channel order is canonical; shells reorder. Every bus the ABI carries (main in, main out, sidechain) lists its channels in the SDK's order: the CLAP surround order of `openplugin_core::layout` (`SpeakerLayout::surround_map`), ambisonic buses in ACN. The ABI never exposes a host's order (VST3 speaker arrangements, Audio Unit layout tags, Pro Tools film order). A shell reorders at its own edge, between the host's buffers and the pointer arrays it hands to `op_shell_process_events`.

`op_shell_layout(index, &layout)` describes layout `index` (no instance needed). `OpLayout.input`, `.output` and `.sidechain` are `OpBus` values with a `kind` (`OP_BUS_ABSENT`, `MONO`, `STEREO`, `SURROUND`, `AMBISONIC`, `DISCRETE`, the `SpeakerLayout` kinds), a `channels` count, and `roles[i]`, the CLAP surround id of channel `i` (FL 0, FR 1, FC 2, LFE 3, BL 4, BR 5, and so on). Stereo is FL, FR. `roles[i]` is `OP_ROLE_NONE` (0xFF) for mono, ambisonic and discrete buses and past channel 16. A shell builds its reorder table from these roles and does not repeat `layout.rs`. `name` is the layout's label. A missing sidechain is `OP_BUS_ABSENT` with 0 channels.

### Layout selection

`op_shell_layout_count()` is how many layouts the plugin offers; index 0 is its default. `op_shell_set_layout(instance, index)` selects one before the first block: it calls `Plugin::set_layout` and `prepare_layout`, and resizes the main and sidechain scratch to the layout's widths (main width is the larger of input and output, at least 1). It allocates and waits for a running block (at most two seconds), so it belongs to the activation step on the main thread. It returns 0, changing nothing, for a bad index, a layout the plugin refuses, or a timeout. `op_shell_create` still takes a channel count of 1 or 2; a shell that wants more selects a layout afterwards. `op_shell_layout_selected` reads the index back.

### The block

```c
OpProcess args = { sizeof args, frames, inputs, in_ch, out_ch, outputs,
                   sidechain, side_ch, event_count, events, &transport };
op_shell_process_events(instance, &args);
OpMidiEvent out[64];
uint32_t n = op_shell_midi_out(instance, out, 64);
```

- Audio is planar pointer arrays. `inputs` may be NULL with `input_channels` 0 (an instrument gets silence). One input channel feeds every channel of a wider engine bus. A NULL channel pointer reads as silence on an input and is skipped on an output. Inputs may alias outputs. Non-finite input samples read as 0.
- `struct_size` is `sizeof(OpProcess)` as the shell compiled it. A smaller value is refused, so fields can be appended later.
- Events (`OpEvent`): note on, note off (channel, note, velocity), raw 3-byte MIDI, and a parameter change as a plain or normalized value, each at a sample `offset` below `frames`. The list may be in any order; it is stably sorted. Delivery follows the CLAP bridge: the block is cut at each distinct offset, the events at that offset are applied (notes and MIDI reach the plugin at offset 0 of the next piece, parameters reach the plane), then the next piece is processed, so a parameter change is sample-accurate. Raw MIDI `0x9n` and `0x8n` reach `note_on_channel` / `note_off`, anything else `Plugin::midi`.
- Transport (`OpTransport`): `flags` carry playing and recording and say which fields the host knows (`OP_TRANSPORT_HAS_TEMPO`, `HAS_SIGNATURE`, `HAS_BEATS`, `HAS_SECONDS`); unknown fields take the `Transport` defaults. NULL keeps the previous transport and does not call `Plugin::set_transport`.
- Sidechain: `sidechain` and `sidechain_channels` (or NULL and 0). It reaches `Plugin::process_buses`; a plugin whose layouts have none ignores it. Channels the host did not send read as silence.
- MIDI output: after the block, `op_shell_midi_out(instance, out, capacity)` copies up to `capacity` `OpMidiEvent` (offset in the block, three bytes) into the caller's buffer and returns the count; call again for more. The engine keeps `OP_MAX_MIDI_OUT` (1024) events per block; extra events are dropped and counted by `op_shell_midi_dropped`. The next block clears what was not read. No allocation.
- Offline: `op_shell_set_offline(instance, 1)` reaches `Plugin::set_offline` at the start of the next block, with the same momentary-parameter release as CLAP.
- Kind: `op_shell_kind()` is `OP_KIND_INSTRUMENT` when `PluginInfo::is_instrument` is set or the category is `Instrument`; `OP_KIND_NOTE_EFFECT` when the plugin is not an instrument, writes notes (`note_ports().output`) and none of its layouts has an audio output; otherwise `OP_KIND_EFFECT`. `op_shell_note_ports()` returns `OP_NOTE_PORT_INPUT` and `OP_NOTE_PORT_OUTPUT` bits. No new `PluginInfo` field was needed.

### Refusals

`op_shell_process_events` returns 0 and touches no audio, no plugin and no parameter for: a NULL instance or `args`, a `struct_size` below the current struct, a NULL array with a non-zero count, more than 64 channels in any bus, more than `OP_MAX_EVENTS` (1024) events, or `frames` above the size given to `op_shell_create`. An individual bad event is skipped and the block still runs: an offset at or past `frames`, an unknown kind, a channel above 15, a note or velocity above 127, a raw message that is not a status byte plus two data bytes, a non-finite parameter value. A parameter index past the end is ignored by the plane. A block that starts during a state call is passed through dry (events lost) and returns 1, as for `op_shell_process`.

Tests: `crates/openplugin-ffi/tests/shell_events.rs` (notes, sorted and split delivery, MIDI out in pages, parameter changes at offsets, transport, sidechain, layouts and roles, selection, offline, kind, the old entry point, hostile input) and the events section of `shell_no_alloc.rs` (zero allocations and frees in the whole events path, refusals included).

## Plugin state

`op_shell_save_state` and `op_shell_load_state` carry the whole plugin state across the ABI: the parameter plane and the plugin's own chunk (`Plugin::save_state` / `load_state`) in one opaque blob, the OPCH session of `openplugin_core::encode_session`. A shell stores the blob as its host state and hands it back later. The VST3 shell (see VST3 state), the Audio Unit shell (see Audio Unit state) and the AAX shell (its state chunk, payload version 2) call them.

```c
uint32_t op_shell_save_state(void* instance, uint8_t* out, uint32_t capacity, uint32_t* needed);
uint32_t op_shell_load_state(void* instance, const uint8_t* data, uint32_t length);
// op_shell_save_state results: OP_STATE_FAILED 0, OP_STATE_OK 1, OP_STATE_TOO_SMALL 2
```

- Save: `out` NULL with `capacity` 0 is a size query. The call returns `OP_STATE_TOO_SMALL` and writes the length to `*needed` (which may be NULL). Allocate that many bytes and call again. `OP_STATE_OK` means the blob is written and `*needed` is its length. If the state grew in between, the second call returns `OP_STATE_TOO_SMALL` again with the new size, so loop until OK. A short buffer is never written. `OP_STATE_FAILED` is a null instance, a null `out` with capacity above 0, a plugin that panics, a state over 4 GiB, or a timeout (below).
- Load: returns 1 or 0. It is all or nothing. The envelope (magic, version, every length, the parameter count, finite values) is checked before the plugin is touched. A corrupt, truncated, extended or foreign blob, an empty one, a null pointer, or a chunk the plugin's `load_state` refuses returns 0 and leaves the parameters and the plugin as they were. A plugin whose `load_state` returns false must have changed nothing itself: the SDK cannot undo a plugin's partial write. A bare OPST parameter plane (what the shells wrote before) still loads, and leaves the plugin's chunk alone.
- ABI: this was added without changing anything existing (`OP_SHELL_ABI` was 1 then; it is 2 since the events block, see Versioning), and a shell that does not call the new symbols builds as before. Both are declared in `op_shell.h` without a guard; a plugin built with `export_shell!` always exports them.

### Threading

A host calls get and set state on the main thread while its audio thread may be inside `op_shell_process`. `Plugin::save_state` takes `&mut self`, so a state call needs the plugin object to itself. One atomic gate decides who has it, and the audio thread never waits:

- `op_shell_process` (and `op_shell_reset`) enter the gate with one compare-exchange, no lock and no allocation. If a state call holds or has asked for the gate, the block is skipped: the input is copied to the output (a dry block, a null right input follows the left), the plugin is not entered, and `process` still returns 1. A `reset` that cannot enter is remembered and runs at the start of the next block, so the Audio Unit's render-thread reset is safe beside a state call.
- A state call takes a mutex against other state calls, sets a request bit, and waits for a block already in flight to end. New blocks see the request bit and skip, so a busy audio thread cannot starve it. The wait is bounded at 2 seconds (`openplugin_ffi::STATE_WAIT`); after that the call fails and changes nothing. The wait happens on the calling (main) thread only.
- Request bit and in-flight bit are one atomic word: for any block and any state call, either the block sees the request and skips, or the call sees the block and waits. No block runs against a half-restored plugin; a load applies the chunk and the plane before it releases the gate, so the next block sees both.

### Parameter-only plugins

A plugin whose whole state is its parameter values returns `true` from `Plugin::state_is_parameters_only` (the SDK's examples do). Its saves and loads never take the gate: a save reads the parameter plane, which the audio thread only reads, and a load validates the whole session and stores the values in the plane, which the engine pulls at the start of its next block. No block is ever skipped. A block that starts while a load is storing values can see some new values and some old ones for that one block. A chunk found in a saved session is ignored, because the plugin declared it has none. The default is `false`: the SDK cannot tell from outside whether a plugin overrides `save_state`, and a wrong guess would drop a chunk. The answer is read once, when the instance is built. CLAP follows the same rule. Tests: `crates/openplugin-ffi/tests/state_param_only.rs` (audio over 4000 blocks is bit-identical to an untouched run while another thread saves and loads; round trips and hostile sessions for both kinds of plugin) and `state_param_only_no_alloc.rs`.

Cost: a block is lost (replaced by dry audio) only when it starts during a call, for as long as `save_state` or `load_state` takes. A host that needs gap-free audio calls these while the transport is stopped or the unit is inactive, when no block is running. Never call them from the audio thread: they allocate and may wait. Before a save the gate holder applies the parameter plane to the plugin, so the chunk matches the values saved beside it; after a load every parameter is pushed to the plugin again on the next block.

The tests are `crates/openplugin-ffi/tests/shell_state.rs` (round trip, size protocol, hostile blobs), `shell_state_threads.rs` (a block during a held save is dry, a save waits for a block in flight, the bounded timeout, and two threads alternating two states against a rendering thread: no torn block, no torn blob) and `shell_state_no_alloc.rs` (zero allocations and frees on the audio thread while a save or a load holds the gate and during repeated calls).

## Editor

A plugin with an editor exports `op_editor_*` (`native/include/op_editor.h`) next to `op_shell_*`, and the shells are configured with `-DOP_EDITOR=ON`. Without that option the shells build as before and a host shows its generic controls. `export_shell!(P, editor = make_editor)` writes these symbols in Rust over `openplugin_dri::cocoa::EditorView`, for any `openplugin_core::Editor` (see [EDITOR.md](EDITOR.md)). The Rust view draws with AppKit, CoreGraphics and libobjc. A static library does not carry its framework links, so `native/CMakeLists.txt` names those frameworks for every target that links the archive, proofs included. That is necessary even with `-DOP_EDITOR=OFF` when the plugin still exports the editor ABI, as `examples/editor` does: the option only decides whether the shells host the view.

| Call | Does |
|---|---|
| `op_editor_size` | size in points the editor opens at |
| `op_editor_size_range`, `op_editor_get_size`, `op_editor_adjust_size`, `op_editor_resize`, `op_editor_set_request_resize` | the `OP_EDITOR_RESIZE` block, which `-DOP_EDITOR=ON` defines for the shells: the sizes the editor takes, its current size, the nearest accepted size, a new size, and the callback an editor uses to ask the host for one |
| `op_editor_create(host)` | makes the editor, bound to no engine; `host` carries the three gesture callbacks |
| `op_editor_view`, `op_editor_attach(parent)` | the `NSView`, and adding it to a host parent view |
| `op_editor_bind(instance)` | shows the engine from `op_shell_create`; null or a destroyed instance shows host values only |
| `op_editor_set_plain(index, plain)` | a parameter value from the host |
| `op_editor_destroy` | removes the view and frees the editor |

Every call is on the main thread. A gesture goes editor to shell to host through `begin_edit`, `perform_edit` and `end_edit`, with plain values, and the host returns the value to the engine as an ordinary parameter change. The editor never writes to the engine.

The shells recreate the engine when the host reconfigures them, so each one binds the open editor again:

- VST3: the processor sends the controller a message (`openplugin.engine`) when it creates or destroys its engine. This needs the processor and controller in one process, connected by the host. A host that does not connect them gets a working editor without meters.
- Audio Unit: the Cocoa view polls its Audio Unit 20 times a second for the engine and the parameter values. On the same timer it logs any failed initialize or render status, because a host renders silence for a failed block and reports nothing. The view class names carry the product name and version, because Objective-C class names are global in the host process.
- AAX: the view reads the engine through `GetCustomData` and sets values through `AAX_IParameter` (`Touch`, `SetValueWithFloat`, `Release`).

`op_editor_bind` must tolerate a pointer that is no longer a live instance. `openplugin_ffi::shell` keeps a table of live instances. `op_editor_bind` hands the editor the instance's `Plugin::editor_state` only when the pointer is in that table.

## Audio Unit reset

A host may call `AudioUnitReset` from its main thread while its render thread is inside the engine, and `op_shell_reset` is exclusive with `process`. The Audio Unit shell therefore only marks the reset, and the render thread performs it at the start of its next block.

## Audio Unit state

The Audio Unit shell overrides `SaveState` and `RestoreState`, the two calls behind `kAudioUnitProperty_ClassInfo`. The dictionary keeps every key `AUEffectBase` writes (version, type, subtype, manufacturer, `data`, name), so hosts and presets stay standard, and gains one more: `OpenPluginState`, CFData holding the blob of `op_shell_save_state`.

- Save: the unit's parameter values are stored into the engine first (the engine otherwise sees them only at the next block), then the blob is fetched with the size protocol: query with `(NULL, 0)`, allocate `*needed`, call again, repeat while the result is `OP_STATE_TOO_SMALL` (up to 8 times). Without an engine (before Initialize) the state held since the last restore is written, if any. If the plugin cannot save, the key is left out and the parameters still save.
- Restore, key present: the blob goes through `op_shell_load_state` first. A refused blob (corrupt, truncated, foreign, a chunk the plugin refuses, or a value of the wrong type under the key) refuses the whole dictionary with `kAudioUnitErr_InvalidPropertyValue` and nothing changes: not the plugin chunk and not the parameters the base keys carry. An accepted blob is followed by the base restore, and then the unit's parameters are read back from the engine, so where the two disagree the blob wins. If the base restore fails after the blob loaded, the earlier state is loaded back.
- Restore, key absent (a preset from before this key): the base restore only, as before; the plugin's chunk is left as it is.
- Before Initialize there is no engine. The blob is then checked on a scratch engine (`op_shell_create` at the unit's sample rate, two channels), refused or accepted by the same rule, kept, and loaded into the real engine at Initialize. Uninitialize keeps the engine's state the same way for the next Initialize. A parameter set between the restore and Initialize is kept.
- Threads: both calls run on the host's main thread and use only `op_shell_save_state`, `op_shell_load_state` and the atomic parameter stores. The shell does not call `op_shell_reset` from them; reset stays on the render thread (Audio Unit reset). A block that starts during a state call is replaced by the dry input, as the ABI says (see Threading).

## Audio Unit bypass

The Audio Unit shell owns `kAudioUnitProperty_BypassEffect`. `AUEffectBase` would copy the input to the output with no delay and reset the plugin when bypass ends, so the shell turns that off (`ShouldBypassEffect` is false, and the property is handled in `SetProperty`). The plugin keeps running while bypassed, so leaving bypass finds it warm. The shell mixes two signals:

- the dry signal, the input delayed by `op_shell_latency` samples, the same value the unit reports as `kAudioUnitProperty_Latency`;
- the plugin output.

A switch moves the mix linearly over 10 ms. Settled bypass is the delayed input exactly. The delay line and the scratch buffers are allocated in `Initialize`, so rendering allocates nothing. A reset (`AudioUnitReset`) clears the delay line on the render thread, with the engine reset described above. The cost is that a bypassed unit still pays for its plugin's CPU.

## Tail

`export_shell!` always exports `op_shell_tail_seconds(instance)`: seconds of ring-out after the input stops, infinity for an endless tail. The value is `Plugin::tail` as of the last processed block. `tail` is called once per block on the audio thread, so it must be cheap and must not allocate. `Tail::Unknown` reports zero. The call works from any thread and never blocks. With `-DOP_TAIL=ON`, VST3 reports it from `getTailSamples`. The Audio Unit reports it as its tail time, with an endless tail given as ten minutes. Without the option VST3 reports no tail and the Audio Unit does not support the property. The SDK example has a finite zero tail, so `-DOP_TAIL=ON` exercises both adapters without a ringing sound.

## Trace

For a host that goes silent and says nothing. Create `<name>-trace.on` in the temporary folder before the first instance is created. `<name>` is the plugin name in lower case, with dashes for spaces and punctuation. The shell then counts creates, destroys, resets, blocks, failed blocks and peaks. The editor's main-thread value updates append a line to `<name>-trace.log` at most four times a second, with the first eight parameter values the engine holds. Without the file, `process` reads one atomic and nothing else. `openplugin_ffi::shell::trace::write` adds a line from plugin code.

## Build

To build a plugin's bundles in every format, with optional signing and notarisation, use `scripts/build_plugin.sh` ([BUILD.md](BUILD.md)). The commands below are what it runs for the shells, and what the proofs use.

The SDK checkouts stay outside this repository. The proofs build `examples/editor`, the `EditorGain` example. Its two parameters are `Gain` (dB) and `Warm` (toggle), and every expected value in the proofs comes from `op_shell_info`, `op_shell_param`, `op_shell_latency` and `op_shell_tail_seconds`, not from constants in the proof.

```bash
CARGO_BUILD_JOBS=2 cargo build --release --lib -p example-editor
cmake -S native -B build-shell -DCMAKE_BUILD_TYPE=Release \
  -DOP_RUST_LIB="$PWD/target/release/libexample_editor.a" \
  -DOP_VST3_SDK=/path/to/vst3sdk \
  -DOP_AU_SDK=/path/to/AudioUnitSDK \
  -DOP_AAX_SDK=/path/to/aax-sdk \
  -DOP_PRODUCT="Example Gain" -DOP_BUNDLE_ID=com.opengrid.example \
  -DOP_VERSION=0.3.1 -DOP_MANUFACTURER=OpenGrid \
  -DOP_AU_SUBTYPE=ExGn -DOP_AU_MANUFACTURER=OpGd \
  -DOP_TAIL=ON -DOP_EDITOR=OFF
cmake --build build-shell -j 2
ctest --test-dir build-shell --output-on-failure
```

`OP_TAIL=ON` is what makes `vst3_proof` and `au_proof` exercise the tail report. A build with `-DOP_TAIL=OFF` still builds and passes the other checks; those two proofs print that the tail check was not built instead of claiming it ran. In this workspace `build-shell` is on the external build volume, not inside the repository, because the internal disk is full.

## Known limits

- Without `OP_EDITOR` there is no editor view: hosts use a generic parameter list, and the AAX view is an empty rectangle. The editor ABI is macOS (`NSView`) only.
- The AAX shell has a page table only with `-DOP_AAX_PAGES=ON`: the build runs `OpenPluginAAXPages`, which writes `<Product>Pages.xml` into the bundle with the parameters in declared order. It needs manufacturer, product and plug-in IDs of four printable characters, so the plugin must set them; the hashed development IDs are refused. Without the option AAX Validator's `test.page_table.load` fails with "Failed to load page tables library".
- AAX has no tail report. This is a format limit, not a gap in the shell. The AAX SDK 2.8.1 (`Interfaces/AAX_Properties.h`, `AAX_Enums.h`, `AAX_IController.h`, `AAX_IEffectParameters.h`, `AAX_IHostProcessor.h` and the `Documentation/Doxygen/dox` guides) has no call, property or notification by which a plug-in states a tail length or a ring-out time; the only latency-like report is `SetSignalLatency`. The one related switch, `AAX_eProperty_Constraint_AlwaysProcess`, stops the host disabling the plug-in's processing when the chain goes silent. It is per effect, costs the whole chain's performance (the SDK says to avoid it unless the host interferes), and carries no duration, so the shell does not set it. `op_shell_tail_seconds` is therefore not used by the AAX shell. The tail contract is checked for VST3 and the Audio Unit only.
- AAX state is one shell chunk (id `OpSt`; layout in `native/aax/OpenPluginAAXState.h`). The shell writes payload version 2: every parameter value, the master bypass, and the blob from `op_shell_save_state` (the parameters plus the plugin's own chunk), so `Plugin::save_state` reaches Pro Tools sessions. `GetChunkSize` asks for the blob size and adds the AAX header; `GetChunk` saves through the size-query protocol (allocate, save, repeat while the state grew) and refuses to write more than `GetChunkSize` promised. The shell reads versions 1 and 2. A version 1 chunk (what 0.3 wrote) restores parameters and bypass and leaves the plugin's own state alone. A load validates the whole chunk first (wrong length, magic, version, parameter layout, blob length, a non-finite or out-of-range value), then applies the blob through `op_shell_load_state`, then the parameters and bypass; a chunk the plugin refuses changes nothing. `CompareActiveChunk` also compares the plugin's blob for version 2. The chunk replaces the SDK's default chunk. `aax_state_proof` drives the real chunk calls on the example, `aax_state_blob_proof` on a stand-in plugin with its own chunk; both build parameter objects without an AAX controller, and Pro Tools itself does not take part. A plugin's state that changes between `GetChunkSize` and `GetChunk` by growing makes `GetChunk` fail rather than overrun the host's buffer; the host asks again.
- The AAX process callback allocates nothing, with or without bypass; `aax_alloc_proof` (the example) and `aax_alloc_latency_proof` (the 200-parameter, 37-sample stub) check it. The proofs cover the callback and the engine it calls, not `EffectInit` or `ResetFieldData`. The delay line, dry buffers and crossfade state are allocated in `ProcessState::prepare`, which `EffectInit` calls.
- The AAX proofs (`aax_process_proof`, `aax_state_proof`, `aax_alloc_proof`, `aax_bypass_proof`, `aax_params_proof`, `aax_state_blob_proof`, `aax_alloc_latency_proof`, `aax_bundle_proof`) cannot run in CI. They link the Avid AAX SDK, which is not redistributable, so they run only on a machine that has the SDK checked out (`-DOP_AAX_SDK`).
- Avid's AAX Validator runs locally against the example bundle with `scripts/aax_validate.sh`; see `docs/AAX_VALIDATOR.md`. It cannot run in CI either.
- AAX host latency is published by `AAX_CEffectParameters::EffectInit` through `SetSignalLatency`, which needs an AAX host controller. `aax_process_proof` checks that the process engine's `op_shell_latency` matches the ABI; it does not instantiate the AAX controller.
- The AAX parameter manager built by `EffectInit` is assembled from the same `op_shell_param` table, but `EffectInit` needs an AAX controller. `aax_state_proof` builds the same parameters through the controller-free part of `EffectInit` (`proofInit`); the direct process proof checks the packet count, the per-parameter IDs and every default value.
- VST3 state (`getState`/`setState`, `native/vst3/OpenPluginVST3.cpp`) keeps the version 1 head and adds the plugin's whole state as a trailer after the bypass flag. Layout, little-endian: `int32` version 1, `int32` parameter count, one `double` normalised value per parameter, `int32` bypass flag, then optionally `uint32` tag `OPSB` (0x4F505342), `int32` trailer version 1, `uint32` length, and the `op_shell_save_state` blob. The head did not change, so a shell that predates the trailer reads the parameters and ignores the rest, and a state without a trailer (version 1, with or without the bypass flag) loads exactly as before and leaves the plugin's chunk alone. The parameter values come from the head, the blob supplies the chunk; after a load the shell pushes the head's values into the engine, so the two agree. A trailer with another tag or version, a length of 0 or above 1 GiB, fewer bytes than its length, bytes after it, or a blob that `op_shell_load_state` refuses makes `setState` return `kResultFalse` before any parameter, the bypass flag or the plugin changes. `getState` asks the size, copies, and repeats while the ABI answers `OP_STATE_TOO_SMALL` (up to 64 tries); a failed save fails `getState` and writes nothing. With the engine active the blob is the engine's; without one `setState` checks the blob on a scratch instance (created with the prepared rate and block size, or 48 kHz and 512) and keeps it for the next `setActive(true)`, and `setActive(false)` saves the engine's state so a later `getState` still carries it. Both calls run on the main thread and allocate; `process` is untouched and the allocation proofs pass. The controller's `setComponentState` reads only the head, so the controller's parameters match without the blob. A shell that predates the trailer loads such a state's parameters and drops the chunk, without an error. Not claimed: that any host stores the larger state intact, or any DAW session.
- Every shell implements host bypass itself. VST3 exposes the standard bypass parameter (`kIsBypass`, id `0x42595053`, outside the plugin's `0..n-1`); while bypassed it outputs the input delayed by `op_shell_latency` with a 10 ms crossfade on switching, starting at the sample offset of the change, and the engine keeps running so switching back is click-free. The delay line is allocated in `setActive`. The bypass flag is stored as a trailing `int32` after the parameter values in the component state; a state without it (written before bypass existed) loads as not bypassed, and an older shell ignores the trailing flag. The Audio Unit shell handles `kAudioUnitProperty_BypassEffect` itself (see Audio Unit bypass). AAX master bypass also outputs the input delayed by `op_shell_latency` with a 10 ms crossfade; its delay line is allocated in `ProcessState::prepare`.
- `vst3_proof`, `vst3_noalloc_proof`, `vst3_bypass_latency_proof`, `vst3_state_proof`, `au_proof`, `au_bypass_proof`, `au_state_proof`, `au_alloc_proof`, `aax_process_proof`, `aax_state_proof`, `aax_alloc_proof`, `aax_bypass_proof`, `aax_params_proof`, `aax_alloc_latency_proof`, `aax_bundle_proof` and `au_editor_proof` are in-process tests. They load the built bundles in the test process, or call the process callback, and compare the adapter with the C ABI. None of them is a Cubase, Logic, Pro Tools or format-validator session.
- `AUEditorProof` (built with `OP_EDITOR`, ctest `au_editor_proof`) registers the Audio Unit bundle in process, without installing it, and opens the editor as a host does: it reads `kAudioUnitProperty_CocoaUI`, instantiates the factory class from the bundle, makes the view with `uiViewForAudioUnit:withSize:` in an offscreen window and checks its size and that the editor is attached. It uninitializes and initializes the unit with the view open, then clicks a point (default: the centre of the Warm toggle of `examples/editor`; `OP_EDITOR_PROOF_CLICK` `x;y;param` overrides it, shared with the VST3 proof). An `AUEventListener` must see a begin gesture, a value change and an end gesture for that parameter, and the unit's value must change to the value the listener saw. It then closes the view, opens a second one, and disposes the unit first. The window is never shown, but AppKit is initialized, so the proof expects a macOS session with a window server; it has not been run headless and is not in CI. It then sets the view's frame as a host does: a huge and a tiny frame give the editor's largest and smallest size (the range is read back from the view), a frame at the largest size resizes the editor's view, a click at the old position of the Warm toggle hits nothing and a click at the scaled position edits the parameter. A double-click on the bare plate changes the container's frame (what an Audio Unit host observes to size its window). It does not check the re-bind beyond the click still working afterwards, and it does not cover a real host's container (another window, a host that does not follow the frame).
- `VST3EditorProof` (built with `OP_EDITOR`) loads the VST3 in process and opens the editor. It re-creates the engine with the editor open. If `OP_EDITOR_PROOF_CLICK` is `x;y;param`, it checks the edits a click makes. It also resizes the view as a host does: `canResize`, `checkSizeConstraint` (the largest and smallest size, and a size off the 3:2 shape brought to it), `onSize`, `getSize`, the `NSView` frame, a click at the old position (nothing) and at the scaled position of the Warm toggle (an edit). A tiny `onSize` stays at the smallest size. A double-click on the bare plate reaches `IPlugFrame::resizeView`, and the view takes the size the frame grants and keeps its size when the frame refuses.
- VST3 parameter changes, bypass included, are sample-accurate. `process` collects every point of every input queue, orders them by sample offset (ties keep arrival order), and renders the block in segments between change points. The values that change at a segment start are set (`op_shell_set_normalized`) before `op_shell_process` for that segment, so a value applies from the segment's first sample; the bypass crossfade starts at the sample of its change. A segment is also capped at the prepared block size, and a block larger than that still works. The scratch for the points is allocated in `setActive` (4096 points, or the parameter count plus one if that is larger). A block with more points than that is thinned per queue: each queue keeps an even share of the capacity, keeping evenly spaced points and always its last one, so the last value of every parameter and of bypass is never lost and a long ramp is approximated by fewer steps; a queue beyond the capacity is ignored. A host sends one queue per parameter, so this limit is reached only by more than about 4000 points per block. Points inside one queue at the same offset are merged by the host SDK, not by the shell. The engine reads parameters at the start of each `op_shell_process`, so the accuracy is that of the plugin: a plugin that smooths a parameter still smooths it from the sample where the new value starts. Starting processing (`setProcessing(true)`) resets the bypass crossfade to the current bypass state. The no-allocation proof is macOS-only (it relies on `malloc_logger`) and covers `process`, not `setupProcessing` or `setActive`, which allocate.
- The AAX controls packet is posted by the shell itself (`GenerateCoefficients` calls `PostPacket`), not by `AAX_CPacketDispatcher`, because a dispatcher packet has a compile-time size. `aax_params_proof` checks what would be posted (`proofTakePacket`); the `PostPacket` call and the data port size declared in Describe need an AAX host, so a 200-value port in Pro Tools is not shown. The AAX SDK sets no limit on the number of parameters or on a native data port's size; the one hard limit found is that a parameter id must be shorter than 32 characters (`kAAX_ParameterIdentifierMaxSize` in `Interfaces/AAX.h`), which the shell does not yet enforce (ids up to 63 characters pass the ABI). `OP_SHELL_AAX_MAX_PARAMS` (64) in `op_shell.h` and `AAX_MAX_PARAMS` in the Rust crate are no longer used by the AAX shell.
- The AAX binary links the external Avid SDK. That binary is not an MIT-only artifact. The SDK license is copied into the bundle resources. Nothing in the build signs it or installs it.

### Resizing in the shells

With `-DOP_EDITOR=ON` the shells define `OP_EDITOR_RESIZE` and follow the editor's size range.

- VST3: `canResize` is false only for a fixed range. `checkSizeConstraint` goes through `op_editor_adjust_size` once the editor is open (before that it clamps to the range alone, without the aspect). `onSize` calls `op_editor_resize`, `getSize` reports `op_editor_get_size`. An editor's request goes to `IPlugFrame::resizeView`; when the frame agrees the view takes the size even if the host does not call `onSize`.
- Audio Unit: the container view overrides `setFrameSize:`. The editor takes the nearest size it accepts and the container keeps the frame the host gave it. An editor's request sets the container's frame size, which a host that observes the view's frame turns into a window size.
- AAX: `GetViewSize` reports the editor's current size. The AAX host never resizes the view by itself, so the only change comes from the editor: its request goes to `AAX_IViewContainer::SetViewSize`, and the editor resizes when the host accepts. No AAX proof covers this, because the view container exists only in Pro Tools; the code is compiled and linked in the `OP_EDITOR=ON` build, and the AAX bundle proofs still pass. An accepted `SetViewSize` and a host that re-reads `GetViewSize` are untested.
